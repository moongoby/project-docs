### 쿼리 5: 코디-상품 매칭 (shooting_id=662)

```sql
SELECT cp.*, c.codyCode, c.codyNumber FROM cody_product_msg cp JOIN cody_msg c ON cp.codyCode = c.codyCode AND cp.shooting_id = c.shooting_id WHERE c.shooting_id = 662;
```

**참고:** 실제 DB에는 `cody_product_msg.cody_id` 컬럼이 없고, `cody_msg`는 `codyCode`, `codyNumber`(camelCase)를 사용함. 위 쿼리는 동일 조건을 `codyCode`·`shooting_id`로 조인한 버전임.

**실행 결과 (전체 행):**  
shooting_id=662 에 해당하는 `cody_msg`·`cody_product_msg` 행이 없어 **0건** 반환됨.

## 보고서에 반드시 포함할 핵심 정보 (명확히 기재)

1. **contents_msg에서 MD 이름이 저장되는 컬럼명**  
   **→ `MDName`** (116 서버 DESCRIBE 결과로 확인 완료.)

2. **cody_product_msg에서 상품코드가 저장되는 컬럼명**  
   **→ `codyProdCode`** (116 서버 DESCRIBE 결과로 확인 완료.)

3. **cody_msg에서 코디번호/코디코드 컬럼명**  
   **→ 코디코드: `codyCode`**, **코디번호: `codyNumber`** (116 서버 DESCRIBE 결과: camelCase 사용.)

4. **shooting_id=662의 MD 이름 실제 값**  
   쿼리 4 실행 결과 **`MDName`: 정다연**.

5. **shooting_id=662의 코디-상품 매칭 데이터**  
   쿼리 5 실행 결과 **0건** (해당 shooting_id에 cody_msg·cody_product_msg 행 없음). 동일 조건 조회 시 실제 DB 컬럼은 `codyCode`, `codyNumber` 사용.

7. **nas_folder_request 최종 테이블 구조**  
   쿼리 8 실행 결과로 `md_name`, `sort_status` 컬럼 포함하여 위 표에 기록 완료.

## 상품코드 → 코디 매칭 쿼리 (참고)

P2 코디폴더 자동분류 시 상품코드로 코디를 찾는 쿼리:

```sql
SELECT cp.*, c.cody_code, c.cody_number
FROM cody_product_msg cp
JOIN cody_msg c ON cp.cody_id = c.id
WHERE c.shooting_id = ?;
```

- `cody_msg.shooting_id` = 촬영 ID (contents_msg.id)
- 상품코드 컬럼은 위 2번에서 확인한 컬럼 사용.
