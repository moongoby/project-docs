## 1. 작업 개요

- **목표:** NAS → 114서버 rsync 동기화 시 exit 12 (Permission denied) 제거.
- **환경:** 서버 rfree-0009.cafe24.com, NAS newtalk@183.96.69.193:2222, 프로젝트 `/data/shortflow`.

## 2. 진단 결과

### 2.1 SSH 키

- `ssh-keygen -y -f /root/.ssh/id_nas` → 공개키 즉시 출력 → **passphrase 없음**.
- `ssh -i /root/.ssh/id_nas -p 2222 newtalk@183.96.69.193 "echo OK"` → **성공**.

### 2.2 rsync 실패 원인

- `rsync -e "ssh -i ..." ...` 실행 시 원격에서 `rsync --server --sender ...` 가 실행되는 순간 **"Permission denied, please try again."** 발생.
- **원인 1:** Synology DSM이 SSH를 통해 실행되는 **`rsync --server` 명령을 차단**하는 것으로 판단됨 (보안 정책).
- **원인 2:** 스크립트의 NAS 소스 경로가 잘못됨.  
  - 기존: `/volume1/newtalk_nas/★웹팀 작업폴더/릴스 영상/`  
  - 실제: **`/volume1/★웹팀 작업폴더/릴스 영상/`** (공유폴더가 `newtalk_nas`가 아님).

### 2.3 전용 키(id_nas_cron) 시도

- cron용 전용 키 `id_nas_cron` 생성 후 NAS에 공개키 등록함.
- `ssh ... "echo OK"` → 성공, **`rsync --server` 동일하게 Permission denied** → 키 문제가 아니라 **rsync 서버 실행 차단**으로 결론.

## 3. 변경 사항

### 3.1 적용한 해결 방안

1. **NAS 소스 경로 수정**  
   - `NAS_SRC` 를 `/volume1/★웹팀 작업폴더/릴스 영상` 으로 변경 (trailing slash 제거 후 스크립트 내부에서 사용).
2. **동기화 방식 변경: rsync → tar over SSH**  
   - Synology에서 `rsync --server` 가 막혀 있어, **tar over SSH** 로 전체 디렉터리 동기화하도록 변경.
   - 방식: `ssh ... "cd \"${NAS_SRC}\" && tar cf - ." | tar xf - -C "${LOCAL_DST}"`.

### 3.2 스크립트 수정 요약

- `scripts/sync_nas_to_server.sh`  
  - `NAS_SRC` 경로 수정.  
  - rsync 호출 제거, ssh + tar 파이프라인으로 교체.  
  - 실패 시 `PIPESTATUS[0]`(ssh), `PIPESTATUS[1]`(tar) 모두 반영해 exit 코드 설정.
- `.env.example`  
  - NAS 관련 항목은 기존 유지 (스크립트는 내부에서 `NAS_KEY` 등 직접 사용).

### 3.3 백업

- 백업 디렉터리: `/data/shortflow/backups/20260223_133229/`
- 포함: `sync_nas_to_server.sh`, `crontab_backup.txt`

## 5. 주의사항 / 후속 작업

- **전체 동기화 시간:** tar로 전체 디렉터리를 매번 덮어쓰므로, 데이터량에 따라 수 분 이상 걸릴 수 있음. cron 주기(예: 30분)는 유지 가능하나, 필요 시 주기 조정 검토.
- **확장자 필터:** 기존 rsync의 `--include='*.MOV'` 등 필터는 제거됨. 현재는 **해당 폴더 전체**를 동기화하며, 파일 수 통계만 MOV/mp4 등으로 집계.
- **SSH 키:** passphrase 없음이 확인되었으며, 보고서에는 키 자체/비밀번호 미기재.
- **project-docs:** 동기화 스크립트 실행 후 `docs/reports` 등 반영 여부 확인 권장.
