## 2. 변경·추가 사항

### 2.1 대시보드 기획문서

- **파일:** `docs/plans/saas_dashboard_plan.md`
- **내용:** 목적, 기술 스택, 화면 구성(비로그인/로그인 후/대시보드/정적), API 연동, 인증·멀티테넌트 연동, 결제 연동 전 범위, 단계별 일정, 1차 목표 파일 구조

### 2.2 멀티테넌트 (SQL)

- **파일:** `sql/005_tenants_channels_rls.sql`
  - `tenants`: id, owner_id(REFERENCES auth.users(id)), email, display_name, plan, plan_expires_at
  - `channels`: id, tenant_id, platform, channel_name, external_id, oauth_token_encrypted
  - `daily_picks`, `jobs`, `scripts`, `videos`, `analytics`에 `tenant_id` 컬럼 추가(nullable, 기존 데이터 호환)
  - RLS 활성화 및 정책: tenants(본인 소유), channels(본인 tenant), 나머지(tenant_id = 본인 tenant 또는 null)
- **파일:** `sql/006_subscriptions.sql`
  - `subscriptions`: tenant_id, plan, status, current_period_start/end, external_id, external_provider
  - RLS: 본인 tenant만 접근

**적용 방법:** Supabase 대시보드 → SQL Editor에서 005 실행 후 006 실행. (auth.users FK는 Supabase 환경에서 동작.)

### 2.3 SaaS 대시보드 (Next.js)

- **경로:** `saas-dashboard/`
- **구성:**
  - **앱:** Next.js 14, TypeScript, Tailwind, App Router
  - **라우트:** `/`(랜딩), `/login`, `/signup`, `/dashboard`(Overview), `/dashboard/channels`, `/dashboard/jobs`, `/dashboard/products`, `/dashboard/billing`, `/dashboard/settings`, `/terms`, `/privacy`
  - **인증:** Supabase Auth (`@supabase/supabase-js`). 로그인/회원가입 폼, 회원가입 시 `tenants` 행 생성(owner_id=user.id, plan=free)
  - **대시보드 레이아웃:** 인증 필수, Header(이메일·플랜·로그아웃), Sidebar, Footer(통신판매업 신고번호·이용약관·개인정보처리방침)
- **환경 변수:** `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `NEXT_PUBLIC_BUSINESS_REGISTRATION_NUMBER` (saas-dashboard/.env.local.example 및 .env.example에 반영)
- **Docker:** docker-compose에 `saas-dashboard` 서비스 추가(포트 3000, 빌드 시 NEXT_PUBLIC_* build args 전달)

### 2.4 결제 구조(API 연동 전)

- **DB:** `subscriptions` 테이블(006)로 플랜·상태·기간·외부 결제 ID 저장 준비
- **UI:** `/dashboard/billing`에서 현재 플랜·다음 결제일 표시, 요금제 카드(무료/스타터/프로/비즈니스), “결제하기”는 비활성 + “연동 예정” 문구

## 3. 테스트 방법

1. **Supabase**
   - 005, 006 SQL 실행 후 `tenants`, `channels`, `subscriptions` 테이블 및 RLS 확인
   - Authentication → Providers에서 이메일/비밀번호 활성화

2. **로컬(Node 설치 환경)**
   ```bash
   cd /data/shortflow/saas-dashboard
   cp .env.local.example .env.local
   # .env.local에 NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY 설정
   npm install
   npm run dev
   ```
   - http://localhost:3000 접속 → 랜딩 → 회원가입 → 대시보드 진입 → 채널/작업/상품/요금/설정 페이지 확인

3. **Docker**
   ```bash
   cd /data/shortflow
   # .env에 SUPABASE_URL, SUPABASE_KEY, NEXT_PUBLIC_BUSINESS_REGISTRATION_NUMBER(선택) 설정
   docker compose build saas-dashboard
   docker compose up -d saas-dashboard
   ```
   - http://localhost:3000 접속

## 4. 주의사항·후속 작업

- **Supabase Auth:** 이메일 확인(Confirm email)이 켜져 있으면 가입 후 메일 링크 확인까지 해야 로그인 가능. 테스트 시에는 끄거나, 확인 없이 로그인 허용 설정 사용.
- **기존 Worker/파이프라인:** 기존 `jobs`/`daily_picks` 등은 `tenant_id`가 null이므로 RLS에서 “tenant_id IS NULL OR tenant_id IN (본인 tenant)”로 계속 조회 가능. 신규 회원 데이터만 tenant_id가 설정됨.
- **결제 API 연동 시:** `subscriptions`에 external_id·external_provider 저장, 결제 성공 시 tenants.plan·plan_expires_at 갱신, `/dashboard/billing`에서 실제 결제 요청 호출 추가.
- **이용약관·개인정보처리방침:** `/terms`, `/privacy`는 현재 플레이스홀더. 실제 문구 작성 후 교체 필요.
- **통신판매업 신고번호:** `NEXT_PUBLIC_BUSINESS_REGISTRATION_NUMBER` 설정 시 Footer에 표시됨.
