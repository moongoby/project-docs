# Phase 14: n8n 스케줄링 구현

**작성일시:** 2026-02-13
**작업 유형:** 신규 개발
**상태:** 완료
**관련 파일:** `worker/main.py`, `n8n/daily_workflow.json`, `n8n/import_workflow.sh`

---

## 1. 작업 개요

Worker API에 일일 자동 실행(/api/v1/pipeline/daily) 및 전체 배치(/api/v1/pipeline/batch) 엔드포인트를 추가하고, n8n 매일 오전 9시(Asia/Seoul) 트리거 워크플로우 JSON 및 임포트 스크립트를 구성하였다.

## 2. 변경 사항

### 2.1 Worker API

- **POST /api/v1/pipeline/daily**
  - Supabase daily_picks에서 오늘 날짜·상태 pending인 픽을 조회, 없으면 status active/pending인 픽 중 랜덤 1건 선택.
  - Job 생성 후 파이프라인을 백그라운드에서 실행하고 즉시 응답.
  - 응답: `{ success, message, data: { job_id, pick_id, status: "started" } }`. 픽 없으면 `status: "no_picks"`.

- **POST /api/v1/pipeline/batch**
  - Body: `{ "pick_ids": [1,2,3] }` 또는 `{}`(미지정 시 전체).
  - 미지정 시 daily_picks에서 status active/pending인 id 목록 조회.
  - 각 pick_id에 대해 Job 생성 후, 한 번에 순차 실행하는 백그라운드 태스크 등록.
  - 응답: `{ success, message, data: { jobs: [{ job_id, pick_id }, ...], status: "started" } }`.

- **PipelineBatchRequest** 모델: `pick_ids: Optional[list[int]] = None`.

### 2.2 n8n 워크플로우 (n8n/daily_workflow.json)

- **Schedule Trigger:** cron `0 9 * * *`, timezone `Asia/Seoul` (매일 09:00).
- **HTTP Request:** POST `http://worker:8000/api/v1/pipeline/daily`, timeout 30s, onError continue.
- **IF Success:** `$json.success === true` 분기.
- **Success / Failure Branch:** noOp 노드(추가 알림·Slack은 편집으로 연결 가능).

### 2.3 n8n 임포트 스크립트 (n8n/import_workflow.sh)

- n8n API `POST /api/v1/workflows`로 daily_workflow.json 전송.
- 환경변수: `N8N_URL`(기본 http://localhost:5678), `N8N_AUTH_USER`, `N8N_AUTH_PASSWORD` (또는 .env의 N8N_BASIC_AUTH_*).
- 옵션: `./import_workflow.sh --activate` 로 워크플로우 활성화(PATCH active: true).
- API 미지원/실패 시 수동 임포트 안내 출력.

## 3. 테스트 결과

- main.py 린트 오류 없음. API는 동일 Docker 네트워크 내에서 `curl -X POST http://worker:8000/api/v1/pipeline/daily` 등으로 확인 가능.

## 4. 주의사항 / 후속 작업

- n8n에서 worker 호출 주소: `http://worker:8000` (Docker 내부). 외부에서는 호스트:8000 사용.
- 파이프라인은 비동기이므로 두 엔드포인트 모두 즉시 응답 후 백그라운드 실행.
- .env의 AUTO_UPLOAD=false 유지 권장.
- n8n 버전에 따라 Schedule Trigger 파라미터(rule.interval 등)가 다를 수 있음. 임포트 후 편집기에서 한 번 확인·저장 후 활성화 권장.
- Slack 알림이 필요하면 Failure Branch 또는 Success Branch에 Slack 노드 추가.
