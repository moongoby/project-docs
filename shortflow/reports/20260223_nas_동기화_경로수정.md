## 3. 테스트 결과

### 3-1. NAS 경로 접속 (Step 1)

- `ssh nas "ls -la '...'"` / `find ...` 실행 시, 한글·특수문자(★) 경로가 SSH 단일 명령 인자로 넘어가면서 인코딩 깨짐으로 **No such file or directory** 발생. 터미널 단일 라인에서의 한글 전달 한계로 판단.
- **SSH 단독 접속:** `ssh -i /root/.ssh/id_nas -p 2222 newtalk@183.96.69.193 "echo OK"` → **성공 (OK)**

### 3-2. rsync 동기화

- 수동 실행: `bash /data/shortflow/scripts/sync_nas_to_server.sh` → **exit 12**
- 로그: `Permission denied, please try again.` / `rsync: connection unexpectedly closed (0 bytes received so far) [Receiver]`
- 동일 `-e "ssh -i ... -p 2222 ..."` 옵션으로 **rsync만** 실행해도 동일 실패. SSH 단독은 성공하므로, **rsync가 SSH 자식 프로세스로 실행될 때 인증 실패**로 추정.
- **가능 원인:** `id_nas` 키에 비밀번호가 있는 경우, cron/비대화형에서는 입력 불가로 Permission denied 발생. 대안: 비밀번호 제거한 전용 키 사용, 또는 ssh-agent에 등록 후 cron에서 `SSH_AUTH_SOCK` 전달.

### 3-3. 기타 검증

- 스크립트 문법·실행 권한(`chmod +x`): 정상
- 로그 파일: `logs/nas_sync_YYYYMMDD.log`에 소스 경로 및 실패 메시지 정상 기록
- `/data/styleflow/raw/`: 기존 데이터만 존재, 이번 rsync로 추가 수신된 파일 없음

## 4. 주의사항 / 후속 작업

- **NAS 경로:** 한글·특수문자(★) 포함 → 스크립트/rsync에서 경로는 항상 따옴표로 감싸서 사용(현재 스크립트 반영됨).
- **cron:** `~/.ssh/config` 미적용 가능성 있음 → 스크립트에서 호스트/포트/키 명시 유지.
- **Permission denied 해결을 위한 후속 권장:**
  1. `id_nas` 키에 비밀번호가 있다면, cron용으로 **비밀번호 없는 전용 키** 생성 후 NAS에 공개키 등록.
  2. 또는 ssh-agent에 `id_nas` 추가 후, cron 작업에서 `SSH_AUTH_SOCK` 등 필요한 환경변수 전달.
- **동기화 성공 후:** `crontab -l`로 NAS 동기화 항목 확인, `logs/nas_sync_*.log` 및 `/data/styleflow/raw/` 파일 수 점검 권장.
