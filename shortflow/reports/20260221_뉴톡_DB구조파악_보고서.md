# 뉴톡 DB 전체 구조 파악 및 릴스 자동화 핵심 데이터 확인

**작성일시:** 2026-02-21
**작업 유형:** 설정 변경 / 점검
**상태:** 완료 (autoda DB 접속 후 쿼리 실행 및 결과 반영)
**관련 파일:** `scripts/newtalk_db_schema_check.sql`, `scripts/run_newtalk_schema_check.py`

---

## 1. 작업 개요

뉴톡(Newtalk) MySQL DB의 전체 구조를 파악하고, ShortFlow 릴스 자동화에 필요한 상품·촬영·코디 관련 테이블 및 시크블랙·촬영완료 데이터를 확인하기 위해 1~3단계 쿼리를 정리하고, SQL 파일 및 Python 실행 스크립트를 추가했다. 실제 DB 접속 정보는 프로젝트에 없으므로, 본 보고서는 실행 방법과 쿼리 목록을 정리한 가이드이며, **실행 결과는 뉴톡 DB 접속 후 아래 방법으로 확보한 뒤 이 보고서에 정리하면 된다.**

---

## 2. 변경 사항

### 2.1 추가된 파일

| 파일 | 설명 |
|------|------|
| `scripts/newtalk_db_schema_check.sql` | 1~3단계 전체 쿼리 (MySQL 클라이언트에서 직접 실행용) |
| `scripts/run_newtalk_schema_check.py` | 환경변수로 뉴톡 DB 접속 후 동일 쿼리 자동 실행, 결과 stdout 또는 파일 저장 |

### 2.2 쿼리 단계 요약

**1단계: DB 전체 구조 파악**
- `SHOW DATABASES;`
- `USE newtalk;` (DB명이 다를 수 있음: newtalk_db, pick_newtalk 등)
- `SHOW TABLES;`
- 상품 관련: `SHOW TABLES LIKE '%product%'`, `'%goods%'`, `'%item%'`
- 촬영/코디 관련: `SHOW TABLES LIKE '%shoot%'`, `'%codi%'`, `'%photo%'`, `'%content%'`

**2단계: 핵심 테이블 구조 확인**
- `DESCRIBE products;`, `DESCRIBE shooting;`, `DESCRIBE codi;`
- `SELECT * FROM products LIMIT 1;`
- `SELECT * FROM shooting ORDER BY id DESC LIMIT 5;`

**3단계: 릴스 자동화 핵심 데이터 확인**
- 시크블랙 상품: `SELECT * FROM products WHERE brand LIKE '%시크블랙%' OR brand LIKE '%chicblack%' ORDER BY id DESC LIMIT 10;`
- 촬영완료 코디: `SELECT * FROM codi WHERE status = '촬영완료' ORDER BY id DESC LIMIT 10;`

## 3. 실행 방법

### 방법 A: MySQL 클라이언트에서 SQL 파일 실행

```bash
mysql -h <호스트> -u <사용자> -p < scripts/newtalk_db_schema_check.sql
```

또는 접속 후:

```bash
mysql -h <호스트> -u <사용자> -p
mysql> source /data/shortflow/scripts/newtalk_db_schema_check.sql
```

- 1단계에서 DB 이름 확인 후, `USE newtalk;`를 실제 DB명으로 바꾸거나 해당 라인만 수정해 실행할 것.

### 방법 B: Python 스크립트 (결과를 파일로 저장 가능)

환경변수 설정 (`.env` 또는 export):

- `NEWTALK_DB_HOST` (필수)
- `NEWTALK_DB_USER` (필수)
- `NEWTALK_DB_PASSWORD` (필수)
- `NEWTALK_DB_NAME` (선택, 기본값: newtalk)
- `NEWTALK_DB_PORT` (선택, 기본값: 3306)

실행:

```bash
pip install pymysql
python3 scripts/run_newtalk_schema_check.py
```

결과를 파일로 저장:

```bash
python3 scripts/run_newtalk_schema_check.py --out data/temp/newtalk_schema_result.txt
```

- 테이블명(products, shooting, codi)이 실제 스키마와 다르면 스크립트 내 쿼리 또는 SQL 파일을 1단계 결과에 맞게 수정한 뒤 다시 실행할 것.

## 5. 주의사항 / 후속 작업

- **접속 정보 보안:** DB 비밀번호는 이번 1회 실행에만 사용했으며, 코드/설정 파일에 저장·커밋하지 말 것. 운영 시에는 환경변수 또는 시크릿 관리만 사용할 것.
- autoda는 **products/shooting/codi**가 아닌 **goods / cody_msg / cody_product_msg** 구조이므로, 릴스 연동 스크립트·SQL은 autoda 스키마에 맞게 작성할 것.
- BizProgress 코드(A1~P2 등) 중 “촬영완료”에 해당하는 값을 업무 담당자에게 확인한 뒤, 자동화 조건(예: J2·H2 이상)을 정할 것.
- 후속: ShortFlow와 autoda 연동 설계 시 **goods ↔ daily_picks**, **cody_msg/cody_product_msg ↔ 촬영 완료 소스** 매핑 및 동기화 주기 정의.
