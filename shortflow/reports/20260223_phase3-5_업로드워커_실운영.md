### 2.2 Step 1 – crontab 상태 (반영 후)

업로드 관련 라인만 정리한 **crontab 등록 내용**:

```cron
# === ShortFlow YouTube 업로드 스케줄 ===
# 09:00 KST → korea_walker (±30분 랜덤 오프셋 스크립트 내 적용)
0 9 * * * /bin/bash /data/shortflow/scripts/scheduled_upload.sh korea_walker >> /data/shortflow/logs/cron_upload.log 2>&1
# 13:00 KST → moongoby
0 13 * * * /bin/bash /data/shortflow/scripts/scheduled_upload.sh moongoby >> /data/shortflow/logs/cron_upload.log 2>&1
# 18:00 KST → korea_walker
0 18 * * * /bin/bash /data/shortflow/scripts/scheduled_upload.sh korea_walker >> /data/shortflow/logs/cron_upload.log 2>&1
# ShortFlow 업로드 로그 로테이션 (7일 보존, 매일 02:00)
0 2 * * * /bin/bash /data/shortflow/scripts/log_rotate.sh
```

- 기존 업로드 3줄은 채널 인자 없이 `cron.log`로만 출력되던 것을 **채널 인자(korea_walker / moongoby)** 전달 및 **cron_upload.log**로 분리.
- **로그 로테이션** 1줄 추가(매일 02:00, 7일 보존).

### 2.3 Step 2 – 로깅 구조

- 일별 로그: `upload_20260223.log` 등 `upload_*.log` 사용.
- **log_rotate.sh** 생성: `upload_*.log` 7일 초과분 삭제, `maintenance.log` 기록. 실행 권한 부여.

### 2.4 Step 3 – scheduled_upload.sh 수정

**수정 여부:** 예.

**요약 diff / 동작 변경:**

- **채널 인자:** `CHANNEL_FOR_RUN="${1:-}"` 추가. 인자가 있으면 그대로 사용, 없으면 기존처럼 시간대별(09→korea_walker, 13→moongoby, 18→korea_walker) 적용.
- **.env 소싱:** `[ -f "${PROJECT_DIR}/.env" ] && source "${PROJECT_DIR}/.env"` 추가.
- **venv 활성화·경로:** 기존 유지. `source "${VENV_DIR}/bin/activate"`, `cd "${PROJECT_DIR}"` 후 `upload_worker.py` 호출.
- **로그 포맷:** 시작/종료 시 `[YYYY-MM-DD HH:MM:SS] 업로드 시작|종료: ${CHANNEL_FOR_RUN}` 형식으로 통일.
- **upload_worker.py** 호출: `--channel "${CHANNEL_FOR_RUN}"` 유지, 로그는 `upload_YYYYMMDD.log`에 append.

### 2.5 Step 4 – 모니터링·로테이션 스크립트

- **upload_monitor.sh:** 오늘 로그 성공/스킵/에러 건수, `uploaded_videos.json` 누적 건수, API 할당량 추정, 디스크 사용량 출력. 실행 권한 부여.
