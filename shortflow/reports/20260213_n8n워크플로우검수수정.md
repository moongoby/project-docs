# Phase 10 n8n 워크플로우 검수 수정

**작성일시:** 2026-02-13  
**작업 유형:** 버그 수정 / 리팩터링  
**상태:** 완료  
**관련 파일:** worker/main.py, worker/tests/test_api.py

---

## 1. 작업 개요

Phase 10 n8n 워크플로우 검수 결과에 따라 asynccontextmanager import 추가, trigger_scoring docstring 명확화, Legacy 엔드포인트 제거, test_api async fixture 수정을 반영하였다.

---

## 2. 변경 사항

### 2-1. main.py — asynccontextmanager import 추가 (치명적)

- **문제:** `@asynccontextmanager` 사용 시 `NameError: name 'asynccontextmanager' is not defined` 로 서버 기동 실패.
- **수정:** 상단에 `from contextlib import asynccontextmanager` 추가.

### 2-2. main.py — trigger_scoring docstring 명확화

- **문제:** 엔드포인트가 실제 스코어링(generate_daily_picks)을 실행하지 않고 readiness만 반환하는데, docstring이 "Run product scoring"으로 오해 소지가 있음.
- **수정:** docstring을 "Check scoring readiness and return trend keywords / pending picks count"로 변경하고, NOTE·TODO로 실제 스코어링은 외부 상품 후보 연동 필요·Phase 11+ 통합 예정임을 명시.

### 2-3. main.py — Legacy 엔드포인트 제거

- **문제:** `/api/generate-scripts`, `/api/generate-video`, `/api/batch-generate`, `/api/jobs/{job_id}`, `/api/retry-job/{job_id}` 5개가 모두 not_implemented 반환으로 새 /api/v1/ API와 혼동 가능.
- **수정:** 위 5개 엔드포인트 및 "# --- Legacy / placeholder endpoints ---" 주석 전체 삭제.

### 2-4. test_api.py — async fixture에 pytest_asyncio 사용

- **문제:** `@pytest.fixture` + async generator client 사용 시 pytest-asyncio 버전에 따라 코루틴이 그대로 반환될 수 있음.
- **수정:** `import pytest_asyncio` 추가, `@pytest_asyncio.fixture` 로 client fixture 변경.

---

## 3. 테스트 결과

- main.py 서버 기동 시 asynccontextmanager NameError 미발생 확인 권장.
- `cd worker && python -m pytest tests/test_api.py -v` 실행 시 async client fixture 정상 동작 확인 권장.

- **스코어링 실행:** 실제 generate_daily_picks 연동은 상품 후보 소스 확정 후 Phase 11+ 에서 진행.
- **BackgroundTasks:** 장시간 백그라운드 작업이 많아지면 Celery 등 별도 task queue 도입 검토.
