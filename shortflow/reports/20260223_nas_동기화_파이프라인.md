## 2. 변경 사항

### 2.1 Step 1 – NAS 접속 현황

| 항목 | 결과 |
|------|------|
| **SSH 접속 (admin@내부/외부 IP)** | 실패 (해당 사용자/키 미사용) |
| **SSH config `nas` 호스트** | 성공. `ssh nas` → newtalk@[NAS-PUBLIC-IP]:[NAS-SSH-PORT], `~/.ssh/id_nas` 사용 |
| **114→NAS 내부 IP ([NAS-IP])** | ping/2222 포트 모두 실패 (114는 Cafe24, NAS와 동일 LAN 아님) |
| **rsync** | 설치됨 (3.1.3) |
| **NAS /volume1/** | 목록 확인됨. `photo` 폴더 없음. 후보: ★제품사진, 뉴톡 등 |

- 실제 동기화는 **외부 IP + SSH config `nas`** 로만 가능.

## 3. 테스트 결과

- **수동 `ssh nas`:** 호스트명, `df -h /volume1` 정상.
- **스크립트 1회 실행:** rsync 단계에서 `Permission denied` → exit 12.  
  - 수동 SSH는 성공하므로, **비대화형(cron/rsync) 환경에서 SSH 인증 실패** 가능성 있음 (SSH 키/agent 또는 NAS 측 비대화형 로그인 제한).
- **NAS_SRC:** `/volume1/photo/` 미존재로, 해당 경로로는 동기화 불가. 실제 촬영 원본 폴더로 변경 필요.

## 4. 주의사항 / 후속 작업

1. **NAS 원본 경로(NAS_SRC)**  
   스크립트 상단 `NAS_SRC="/volume1/photo/"` 를 실제 촬영 폴더로 수정.  
   예: `/volume1/★제품사진/`, `/volume1/뉴톡/` 또는 신규 생성한 공용 폴더.

2. **Permission denied (exit 12)**  
   - cron/스크립트 실행 시 SSH 키가 적용되는지 확인 (`ssh -v nas` 등).  
   - 필요 시 rsync `-e "ssh -i /root/.ssh/id_nas ..."` 처럼 키를 명시.  
   - NAS DSM에서 해당 사용자(newtalk)의 SFTP/rsync 허용 여부 확인.

3. **로그**  
   - `logs/` 및 `*.log`는 `.gitignore`에 포함되어 있음 (커밋 제외).

4. **동기화 성공 후**  
   - `logs/nas_sync_YYYYMMDD.log` 에 성공 로그 및 파일 수 기록됨.

5. **project-docs 동기화**  
   - 작업 완료 후 `bash /data/project-docs/scripts/sync_shortflow.sh` 실행 완료.
