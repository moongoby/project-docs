**작성일시:** 2026-02-13  
**작업 유형:** 신규 개발

**관련 파일:** trend_collector.py, product_scorer.py, test_product_scorer.py, config.py, requirements.txt, sql/002_trends_table.sql

## 1. 작업 개요

트렌드 키워드 수집(TrendCollector)과 상품 점수 산정/일일 선정(ProductScorer)을 구현하였다. Naver Shopping·Google Trends·Coupang Bestseller에서 트렌드를 수집하고, 상품 후보에 대해 수수료·트렌드·가격대·경쟁도·콘텐츠 적합도를 반영한 종합 점수를 매겨 daily_picks에 저장한다.

---

## 2. 변경 사항

### 2-1. worker/services/trend_collector.py
- **상수**: MAX_TRENDS_PER_SOURCE=50, TREND_CACHE_HOURS=6, USER_AGENT.
- **모델**: TrendSource(enum), TrendItem(keyword, source, rank, category, search_volume, growth_rate, related_keywords, collected_at, raw_data), TrendReport(items, sources_collected, sources_failed, collected_at).
- **TrendCollector**: collect_all() → naver_shopping, google_trends, coupang_bestseller 병렬 수집, 실패 시 로그만 하고 예외 전파하지 않음. _collect_naver_shopping (DataLab API, 미설정 시 fallback), _collect_naver_shopping_fallback (스크래핑), _collect_google_trends (RSS), _collect_coupang_bestseller (스크래핑). save_trends_to_db(report) → 001 스키마(source, keyword, score, category, collected_at, metadata) 기준 insert.

### 2-2. worker/services/product_scorer.py
- **상수**: DEFAULT_SCORE_WEIGHTS(commission_rate, trend_score, price_range, competition, content_fit), MIN_SCORE_THRESHOLD=50, MAX_DAILY_PICKS=50.
- **모델**: ProductCandidate, ScoredProduct(total_score, score_breakdown, trend_keywords_matched, estimated_revenue, pick_priority), DailyPickList.
- **ProductScorer**: score_product(product, trend_keywords) → 5개 항목 점수(0–100) 및 가중 합산, estimated_revenue 산출. generate_daily_picks(candidates, trend_keywords, max_picks, min_score) → 필터·정렬·우선순위 부여 후 _save_picks_to_db. _save_picks_to_db → daily_picks 테이블에 picked_date, product_name, category, price, commission_rate, product_url, product_image_url, platform, score, score_detail(JSON), status=pending. get_todays_picks() → 당일 picked_date·status=pending 기준 조회, score 내림차순.

### 2-3. worker/tests/test_product_scorer.py
- test_score_high_commission, test_score_trend_match, test_score_price_sweet_spot, test_score_price_out_of_range, test_score_competition_sweet_spot, test_score_visual_category, test_generate_daily_picks_filtering, test_generate_daily_picks_ordering. DB는 _save_picks_to_db mock.

### 2-4. worker/config.py
- naver_client_id, naver_client_secret 추가(기본값 "").

### 2-5. worker/requirements.txt
- beautifulsoup4>=4.12.0, lxml>=4.9.0 추가.

### 2-6. sql/002_trends_table.sql
- trends 테이블 확장 정의(키워드, 소스, rank, search_volume, growth_rate, related_keywords, UNIQUE(keyword, source, collected_at)). 001 이미 적용된 환경에서는 기존 trends 구조 유지; 002는 확장 스키마 적용 시 사용.

## 4. 주의사항 / 후속 작업

- **트렌드 저장**: 현재는 001 스키마(metadata에 rank 등)로 insert. 002 스키마를 적용한 DB에서는 컬럼 확장 후 upsert(on_conflict) 전환 가능.
- **daily_picks**: 001 스키마에 맞춰 score_detail에 score_breakdown, trend_keywords_matched, pick_priority, estimated_revenue, description 저장. status=pending으로 저장하며, 파이프라인에서 job 생성 후 status 갱신 로직 추가 가능.
- **Naver API**: NAVER_CLIENT_ID, NAVER_CLIENT_SECRET 미설정 시 네이버 쇼핑 fallback 스크래핑 사용. 셀렉터는 실제 페이지 구조에 따라 조정 필요.
