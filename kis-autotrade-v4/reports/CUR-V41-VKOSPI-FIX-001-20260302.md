## 2. 수행한 조치

### [조치 1] collect_vkospi_alt.py `end_date` 수정

**파일**: `scripts/collect_vkospi_alt.py`
**커밋**: `bc5fac1c`

```diff
-        end_date = yesterday
+        end_date = today_str  # yesterday → today: 금요일 T+1 게재 시 즉시 반영
```

3개 분기 모두 적용 (`--backfill`, `--days`, default):

| 분기 | 변경 전 | 변경 후 |
|------|---------|---------|
| `--backfill` | `yesterday` | `today_str` |
| `--days N` | `yesterday` | `today_str` ← **크론 사용 분기** |
| `기본` | `args.end or yesterday` | `args.end or today_str` |

**효과**: 크론 15:50 실행 시 `end_date = 오늘`로 API 요청 → 당일 게재 데이터 즉시 수집 가능

### [조치 2] 크론 `--days` 범위 확대

```diff
-50 15 * * 1-5  collect_vkospi_alt.py --days 5
+50 15 * * 1-5  collect_vkospi_alt.py --days 7
```

**효과**: 주말 포함 7일 범위 확보 → 월요일 크론에서 지난 주 금요일 데이터 커버

| 요일 | 변경 전 커버 범위 | 변경 후 커버 범위 |
|------|-----------------|-----------------|
| 월요일 15:50 | 수~일 (5일) | 화~오늘월 (7일) |
| 금요일 15:50 | 일~목 (5일) | 금~오늘금 (7일) → 당일 포함 |

## 5. 근본 원인 (재확인)

1. **공공데이터포털 API 데이터 T+1~T+2 지연**: API 접근은 24시간 가능하지만 금융위원회 데이터는 T+1 영업일 후 게재. 이것은 외부 요인으로 코드로 해결 불가.
2. **(수정 완료) `end_date=yesterday` 설계 결함**: 당일 게재 데이터를 놓치는 구조 → `today_str` 변경으로 해소.
3. **(정상 확인) 레짐 동기화 오류**: Feb 27 15:55 로그의 `numeric field overflow` (VKOSPI=2885.49)는 과거 일시적 오류. 현재 정상 (54.67). 스키마 NUMERIC(7,2) 적절.
