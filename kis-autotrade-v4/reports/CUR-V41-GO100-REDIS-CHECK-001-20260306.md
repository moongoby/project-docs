## 4. Redis 연결 설정 확인

### 4-1. .env 설정
```
REDIS_HOST=localhost
REDIS_PORT=6379
REDIS_DB=0
REDIS_URL=redis://localhost:6379/0
```

### 4-2. backend/app/core/redis.py
```python
redis_client = aioredis.from_url(
    settings.redis_url,        # redis://localhost:6379/0
    encoding="utf-8",
    decode_responses=True,
)
```

### 4-3. session_memory.py 설정
```python
url = redis_url or os.getenv("REDIS_URL", "redis://localhost:6379/0")
self.redis = redis.from_url(url, decode_responses=True)
```

### 4-4. 독립 Python 프로세스 ping 테스트
```bash
$ /root/kis-autotrade-v4/venv/bin/python3 -c "
import asyncio
import redis.asyncio as aioredis
async def test():
    client = aioredis.from_url('redis://localhost:6379/0', encoding='utf-8', decode_responses=True)
    result = await asyncio.wait_for(client.ping(), timeout=5.0)
    print('ASYNC PING:', result)
    await client.aclose()
asyncio.run(test())
"
ASYNC PING: True
```

**핵심 분석**: 독립 프로세스에서 동일 URL로 aioredis.ping() → `True` (정상). 그러나 실행 중인 FastAPI 앱 내부 `redis_client`는 ping 실패. → **장기 실행 FastAPI 프로세스에서 aioredis 연결 풀 교착(stale connection pool) 상태**.

## 6. 연구소 API 경로 확인

### 6-1. 연구소 API 경로 목록
```python
# backend/app/routers/go100/commander_router.py
@router.post("/research")       # POST /api/go100/commander/research   — 연구 파이프라인
@router.post("/research-lab")   # POST /api/go100/commander/research-lab — ResearchLabAgent 호출

# backend/app/api/v1/admin_router.py
@router.get("/research-lab-status")   # GET /api/v1/admin/research-lab-status
```

### 6-2. 연구소 엔드포인트 호출 결과
```bash
$ curl -s http://localhost:8002/api/v1/admin/research-lab-status
{"status":401,"detail":"Not authenticated",...}

$ curl -s -X GET http://localhost:8002/api/go100/commander/research-lab
{"detail":"Method Not Allowed"}
```

**분석**: 연구소 경로는 등록되어 있음 (404 아님). `/api/v1/admin/research-lab-status`는 인증 필요 (401). T-160의 `404` 결과와 다름 → 라우터 등록 정상화 가능성. POST로만 호출 가능한 경로에 GET 시도 → `405 Method Not Allowed` 정상 응답.

**결론: 연구소 API 경로 자체는 존재. 이전 T-160의 404는 라우터 등록 이전 상태였을 가능성 있음.**
