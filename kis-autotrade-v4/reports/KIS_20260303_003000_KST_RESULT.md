## 근본 원인 2가지

### 원인1: `>>>` 렌더링 제거

Genspark 브라우저(`document.body.innerText`)가 `>>>DIRECTIVE_START`를
`DIRECTIVE_START`(>>> 없음)으로 렌더링.

```
# 매니저가 작성한 원본:       >>>DIRECTIVE_START
# 브라우저 innerText 결과:    DIRECTIVE_START
```

기존 패턴은 `>>>DIRECTIVE_START` 또는 `[DIRECTIVE_START]`만 허용 → plain `DIRECTIVE_START` 미매칭.

### 원인2: 단일 라인 필드 파싱 실패

매니저가 필드를 한 줄에 작성하는 경우:
```
DIRECTIVE_START Task: CUR-GO100-P4A-... Priority: P1 Action: ...
```
기존 `_PRIORITY_RE = re.compile(r'^priority\s*[:：]', re.MULTILINE)` 패턴이
`^`(라인 시작) 앵커 필요 → 라인 중간의 `Priority:` 불일치 → project/priority 필드 없음 → FAIL.

## 수정 내용 (genspark_bridge.py)

### 1. parse_directive() — 3가지 구분자 형식 모두 지원

```python
# 수정 후 패턴 (START~END 완전 블록)
complete_pat = re.compile(
    r"(?:\[DIRECTIVE_START\]|>>>DIRECTIVE_START|DIRECTIVE_START)"  # ← plain 추가
    r"(.*?)"
    r"(?:\[DIRECTIVE_END\]|>>>DIRECTIVE_END|DIRECTIVE_END)",
    re.DOTALL,
)

# START-only 폴백도 동일하게 plain 포함
open_pat = re.compile(
    r"(?:\[DIRECTIVE_START\]|>>>DIRECTIVE_START|DIRECTIVE_START)(.*)",
    re.DOTALL,
)
```
