## 2. 이슈 분석

### 이슈 1: DOM ID 불일치 (kw-trade-list.js ↔ trades.html)

| 항목 | kw-trade-list.js (수정 전) | trades.html 실제 ID |
|------|--------------------------|---------------------|
| 시작 날짜 | `kwFilterDateFrom` | `filter-date-from` |
| 종료 날짜 | `kwFilterDateTo` | `filter-date-to` |

- **결과**: `setDefaultDates()` 호출 시 `document.getElementById()` → null 반환 → 날짜 기본값 미설정
- **영향**: 날짜 필터 없이 전체 105,526건 로드 (불필요한 서버 부하)

### 이슈 2: 한글 종목 검색 HTTP 400

- **원인**: raw 비 ASCII 문자(한글)를 URL에 포함하면 HTTP/1.1 프로토콜 위반
  - `curl "...?q=삼성"` → nginx/uvicorn이 HTTP 400 반환 (정상 거부)
  - URL 인코딩 후 `?q=%EC%82%BC%EC%84%B1` → HTTP 200 (정상 처리)
- **JavaScript 측**: `kw-chart-engine.js`에 `stocks_search` URL만 정의되고 `fetchSearch()` 메서드 없음 → `encodeURIComponent` 처리 불가
- **서버 측**: `v4_trades_unified.py` stocks/search 엔드포인트는 동작하지만 whitespace-only 쿼리 처리 미흡

### 3.2 kw-chart-engine.js — fetchSearch() 추가

파일: `frontend/static/js/kw-chart-engine.js`

```javascript
// ── fetchSearch(q) ────────────────────────────────────────────
// 한글 종목명 자동완성. encodeURIComponent로 한글 URL 인코딩 처리.
KWChartEngine.prototype.fetchSearch = function (q) {
  var encoded = encodeURIComponent((q || '').trim());
  if (!encoded) return Promise.resolve([]);
  return apiFetch(API_URLS.stocks_search + '?q=' + encoded);
};
```

## 5. 한계 사항

- raw 한글 URL (`curl "...?q=삼성"`) → HTTP 400은 HTTP/1.1 RFC 3986 프로토콜 제약으로 수정 불가
  - nginx, uvicorn 모두 raw non-ASCII URL 거부 (정상 동작)
  - 브라우저 fetch API는 자동으로 URL 인코딩하므로 실사용에서 문제 없음
  - kw-chart-engine.js의 `fetchSearch()` + `fetchTrades()`는 `encodeURIComponent` 사용으로 안전
