### 1.2 실시간 분봉 전용 모듈

| 검색 결과 | 설명 |
|-----------|------|
| **분봉 실시간 수집 모듈** | **없음** — `*realtime*`, `*stream*`, `*ws_*` 중 분봉 적재용 모듈 없음 |
| v4_websocket | 체결 알림(`/ws/live-trade`), 시세 틱(`/ws/ticks`) 구독용. **분봉 DB 적재 아님** |
| orderbook_collector | 호가(Orderbook) 실시간 수집 → `v4_orderbook_realtime`. 분봉과 무관 |
| KIS 실시간 체결(H0STCNT0 등) | 코드베이스 내 **분봉 수집에 사용되는 웹소켓 TR 없음** |

**결론**: 실시간 **분봉**을 DB에 쌓는 별도 모듈은 **없음**. 당일 분봉은 “REST 당일분봉 조회”를 **대상 날짜에 당일을 넣는 방식**으로만 수집 가능.

### 1.3 배치 스크립트 vs systemd

| 구분 | 스크립트/서비스 | 사용 코드 | 비고 |
|------|----------------|----------|------|
| cron 배치 | `scripts/minute_batch_cron.sh` | **collect_minute_historical.py** (별도 스크립트) | 16:00·토 02:00. KISAPIClient, 장중 일시중단 |
| systemd | kis-v41-minute-collector | **collector_minute.py** (backend 모듈) | 실전계좌 자동 감지, 병렬 수집 |

**cron 배치**와 **systemd 수집기**는 **서로 다른 진입점**이지만, 동일 API **FHKST03010230** 사용.  
당일 분봉 수집 가능 여부는 “**대상 날짜 목록에 당일이 포함되는지**”에 따라 결정됨.

## 2. 당일(02-23) 분봉 0건 원인

### 2.1 거래일 목록의 출처

- `_get_trading_dates(days)` → `ohlcv_daily`에서 `stock_code = '005930'`인 행의 **DISTINCT date** DESC.
- **당일(2026-02-23)** 이 ohlcv_daily에 **아직 없음** (당일 일봉은 보통 장 마감 후 18:00 cron으로 수집).

### 2.2 현재 ohlcv_daily(005930) 최근 일자

```
20260220, 20260219, 20260213, 20260212, ...
```

- **20260221** (금): 목록에 없음 (일봉 수집 누락 또는 휴장 등 별도 이슈 가능).
- **20260223** (당일): 당일 일봉 미수집 → **trading_dates에 2026-02-23 없음**.

### 2.3 수집 대상 결정 로직

- `run()`에서 `trading_dates = await self._get_trading_dates(days)` 후  
  `(stock, td) not in collected_set` 인 (종목, 날짜)만 큐에 넣음.
- **당일이 trading_dates에 없으므로**, 당일(02-23)은 **한 건도 큐에 들어가지 않음** → **당일 분봉 0건**.

### 2.4 정리

| 원인 | 설명 |
|------|------|
| **1차 원인** | 거래일 목록을 **ohlcv_daily**에서만 가져옴. |
| **2차 원인** | 당일 일봉은 장후(18:00 등)에만 적재되므로, **장중에는 당일 날짜가 ohlcv_daily에 없음**. |
| **결과** | 당일(02-23)이 수집 대상 목록에 포함되지 않아 **당일 분봉 0건**. |

KIS API **FHKST03010230**은 문서상 **당일 분봉 장중 조회 가능**으로 알려져 있음.  
즉, “API 불가”가 아니라 **“대상 날짜 목록에 당일을 넣지 않는 설계”** 때문에 당일 분봉이 수집되지 않는 상태임.
