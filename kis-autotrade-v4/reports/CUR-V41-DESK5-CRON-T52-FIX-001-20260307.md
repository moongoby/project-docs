## 1. 배경 및 문제

T-202 분석에서 식별된 DESK5 파이프라인 단절점 2개를 수정한다.

### 단절점 ① FIX-001 — DESK5 크론 cd 경로 누락

root 개인 crontab에 등록된 DESK5 노드 감지 크론:

```
0 7 * * 1-5 /root/kis-autotrade-v4/venv/bin/python3 -m backend.app.services.node_detector_engine desk5 >> ...
```

`cd /root/kis-autotrade-v4 &&` 없이 `-m backend.app.services.node_detector_engine` 실행 → Python이 현재 작업 디렉터리를 `sys.path`에 삽입하지 못함 → `ModuleNotFoundError: No module named 'backend'` 매일 발생.

**수동 재현 증거 (로그):**
```
/root/kis-autotrade-v4/venv/bin/python3: Error while finding module specification for 'backend.app.services.node_detector_engine' (ModuleNotFoundError: No module named 'backend')
```

파일 위치: `/root/kis-autotrade-v4/logs/node_desk5.log` (매일 07:00 KST 반복)

### 단절점 ② REL-003 — T5-2 조건 논리 모순

기존 T5-2 조건: **120일 박스 상단 돌파**

DESK5 편입 조건은 "바닥권 종목(52주 저가 +20% 이상, MA60 상향전환)" 이다. 바닥권 종목은 120일 최고점 아래에 있으므로 120일 고점 돌파 조건은 논리적으로 충족 불가능 → **20종목 T5-2 트리거 0%** 실증.

**변경 전 (라인 249~253):**
```python
# ── T5-2: N일박스상단돌파 ──
_t5_2_box_days = int(_P5.get("t5_2_box_days", 120))
bars_120 = bars[-_t5_2_box_days:] if len(bars) >= _t5_2_box_days else bars
```

**변경 후 (REL-003):**
```python
# ── T5-2: MA60 기울기 양전환 + 거래량 1.5배 (REL-003) ──
# 구 조건(120일 박스 상단 돌파)은 바닥권 종목에 논리적으로 불가능 → 트리거 0%
_t5_2_vol_mult = float(_P5.get("t5_2_vol_multiplier", 1.5))
_t5_2_vol_period = int(_P5.get("t5_2_vol_period", 20))
vol_avg_ref = _ma(volumes[:-1], _t5_2_vol_period) if len(volumes) >= _t5_2_vol_period + 1 else None
ma60_slope_pos = bool(ma60_d1 and ma60_d2 and ma60_d1 > ma60_d2)
vol_surge_1_5x = bool(vol_avg_ref and volumes[-1] >= vol_avg_ref * _t5_2_vol_mult)
t5_2 = bool(ma60_slope_pos and vol_surge_1_5x)
```

**변경 이유:**
- MA60 기울기 양전환: 바닥권 종목의 추세 전환 신호 (회복 중인 종목만 통과)
- 거래량 1.5배: 단순 회복이 아닌 수요 증가 확인 (noise 필터)
- 기존 ma60_d1, ma60_d2 변수 재활용 (코드 중복 없음)
