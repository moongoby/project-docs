## 3. Task A: 포트폴리오 최적화 연동 (`_run_entry_signals`)

### 3.1 함수 시그니처 변경

# Phase 3 (async 전환 + 포트폴리오 최적화 삽입)

`run()` 메서드에서도 `await self._run_entry_signals(...)` 로 호출 방식을 변경하였다.

### 3.2 삽입점 C — 포트폴리오 최적화 로직

DESK별 후보 종목(`list_picks`) 확정 직후, 주문 생성 전에 다음 3단계가 실행된다.

```
삽입점 C   : DESK별 tickers 확정 → request_portfolio_optimization() 비동기 호출
삽입점 C-2 : weights=0 또는 누락 종목 → 매수 Skip
삽입점 C-3 : 최적 비중(weight) × DESK 할당 자본 → 종목별 매수 수량 재계산
```

**핵심 코드 (요약)**:

```python
# ── [삽입점 C] 포트폴리오 최적화 비중 요청 ────────────────────
weights: Dict[str, float] = {}
if self.config.enable_go100_bridge:
    tickers = [p.get("code") for p in list_picks if p.get("code")]
    alloc = self._desk_alloc.get(desk_id, 0)
    if tickers and alloc > 0:
        try:
            client = Go100BridgeClient()
            opt = await client.request_portfolio_optimization(
                tickers=tickers,
                capital=float(alloc),
            )
            weights = opt.get("weights") or {}
        except Exception as exc:
            # Fallback: 균등 분배 — 브릿지 오류가 매매를 막지 않는다
            eq_w = round(1.0 / len(tickers), 6)
            weights = {t: eq_w for t in tickers}

# ── [삽입점 C-2] 비중 0 또는 누락 종목 매수 Skip ──────────────
if self.config.enable_go100_bridge and weights:
    if weights.get(code, 0.0) <= 0.0:
        continue  # 매수 제외

# ── [삽입점 C-3] 최적화 비중 기반 자본 재계산 ──────────────────
if self.config.enable_go100_bridge and weights and code in weights:
    ticker_capital = alloc * weights[code]
    qty = max(1, int(ticker_capital // open_price))
else:
    qty = self._calculate_position_size(desk_id, open_price, pick.score)
```

### 3.3 설계 원칙

| 속성 | 구현 내용 |
|------|-----------|
| **비동기 호출** | `await request_portfolio_optimization()` — 응답 대기 시 매매 루프 차단 최소화 |
| **Fail-Open** | `BridgeError` 발생 → 균등 분배(Equal Weight) Fallback → 매매 지속 |
| **비중=0 Skip** | `weights.get(code, 0.0) <= 0.0` → `continue` → 해당 종목 매수 제외 |
| **지연 import** | `enable_go100_bridge=False` 시 `Go100BridgeClient` 불필요한 의존성 미로드 |
| **비파괴성** | `enable_go100_bridge=False` 이면 weights=`{}` → 기존 `_calculate_position_size()` 로직 100% 유지 |

## 4. Task B: 브릿지 스위치 활성화

### 4.1 `BacktestConfig` 변경

```python
# Phase 2 (비활성)
enable_go100_bridge: bool = False

# Phase 3 (활성화)
enable_go100_bridge: bool = True
```

기본값이 `True`가 됨으로써 새로운 `BacktestEngineV2` 인스턴스는 자동으로 브릿지를 활성화한다.
기존 테스트·스크립트에서 브릿지를 끄려면 `enable_go100_bridge=False`를 명시적으로 전달하면 된다.

### 5.1 시나리오 1 — weights={} 동작 해설

실제 GO100 서버에 `/portfolio/optimize` 요청 시 `weights={}` 반환되었다.
옵티마이저가 해당 종목들의 **과거 수익률 데이터가 부족**하여 MARKOWITZ 최적화를 수행하지 못한 케이스다.
엔진 내 처리: `weights={}` → `bool({}) == False` → `_calculate_position_size()` Fallback 자동 발동.
