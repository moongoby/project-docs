## Part 1. 데이터 전체 지도

DESK 2의 7개 Condition과 7개 Strategy가 정상 작동하려면 총 4개 계층, 23개 데이터셋이 필요합니다. 이 중 현재 확보된 것, 부분 확보된 것, 미확보된 것을 구분하여 보고합니다.

## Part 2. 백테스트용 히스토리컬 데이터

### 2.1 분봉 데이터 (1분/3분/5분 OHLCV)

현재 상태: v4_minute_bar 테이블에 약 433만 행이 존재합니다. 이 데이터가 DESK 2 백테스트의 기반입니다.

필요 항목은 ticker(종목코드), datetime(분봉 시각), open/high/low/close(시가/고가/저가/종가), volume(거래량), value(거래대금)입니다.

확인이 필요한 사항이 있습니다. 첫째, 수록 종목 범위가 전 종목인지 특정 유니버스인지 확인해야 합니다. DESK 2는 KOSPI+KOSDAQ 전 종목 중 시가총액 상위 500~1,000개를 대상으로 하므로 최소 이 범위가 포함되어야 합니다. 둘째, 수록 기간이 몇 년치인지 확인해야 합니다. 백테스트 Phase 1 기준 최소 1년(250 거래일)이 필요하고, Walk-Forward까지 고려하면 2년 이상이 이상적입니다. 셋째, 1분봉인지 3분봉인지 5분봉인지, 또는 복수 타임프레임이 모두 있는지 확인해야 합니다. 1분봉만 있으면 3분봉·5분봉은 집계로 생성할 수 있습니다. 넷째, 결측 구간이 있는지 확인해야 합니다. 특정 날짜나 종목의 데이터가 빠져 있으면 백테스트 결과가 왜곡됩니다.

Condition별 의존도는 다음과 같습니다. C1(갭)은 시가 산출에 전일 종가+당일 시가가 필요하므로 분봉 필수입니다. C2(ORB)는 09:05~09:20 구간 고가·저가 계산에 1분봉 필수입니다. C3(VI)는 분봉으로 VI 전후 가격 재현이 필요합니다. C4(VWAP)는 분봉 OHLCV로 VWAP를 누적 계산합니다. C5(눌림목)는 A→B→C 패턴을 분봉에서 탐지합니다. C6(업종 후발)은 대장주·후발주 분봉이 동시에 필요합니다. C7(과매도)은 분봉 RSI·볼린저밴드를 계산합니다. 7개 전략 모두 분봉 데이터 없이는 CS 계산이 불가능합니다.

**우선순위: 최우선(P0)**. 현재 확보된 433만 행의 정확한 범위(종목·기간·타임프레임)를 즉시 확인해야 합니다.

### 2.2 일봉 데이터 (Daily OHLCV)

현재 상태: v4_daily_price 또는 유사 테이블이 존재할 것으로 예상되나 정확한 테이블명과 범위 확인이 필요합니다.

필요 항목은 ticker, date, open/high/low/close, volume, value, market_cap(시가총액), shares_outstanding(상장주식수)입니다.

용도는 RVOL 계산의 기준값(20일 평균 거래량) 산출, 볼린저밴드·MA 등 중기 지표의 기준 데이터, 피보나치 되돌림 참조 구간(전일·전주 고저), TIER 엔진의 시가총액 필터링(종목별 시총), 백테스트 시 일별 수익률 집계입니다.

필요 범위는 KOSPI+KOSDAQ 전 종목, 최소 2년(500 거래일), 이상적으로 5년입니다.

**우선순위: 최우선(P0)**. 분봉과 함께 가장 기본이 되는 데이터입니다.

### 2.3 VI(변동성완화장치) 이력 데이터

현재 상태: 미확보 가능성 높음. 별도 테이블 확인 필요합니다.

필요 항목은 ticker, vi_trigger_time(VI 발동 시각), vi_release_time(VI 해제 시각), vi_type(동적/정적, 상한/하한), trigger_price(발동 가격), pre_vi_price(발동 직전 가격), post_vi_first_price(해제 후 첫 체결가), pre_vi_volume_5min(발동 전 5분 거래량)입니다.

용도는 Condition 3(VI 폭발)의 핵심 데이터이며, CHARLIE-VI 전략의 백테스트에 필수입니다. VI 발동 전후 가격·거래량 패턴을 분석하여 진입 타이밍과 수익률을 검증합니다.

확보 방안은 세 가지입니다. 방안 A는 한국거래소(KRX) 정보데이터시스템에서 VI 발동 이력을 다운로드하는 것입니다. 방안 B는 분봉 데이터에서 VI를 역추정하는 것으로, 1분 내 ±6% 이상 변동 후 거래 중단(체결 없음) 구간을 탐지하여 VI 발동을 유추할 수 있으나 정확도가 80~90% 수준입니다. 방안 C는 KIS OpenAPI의 과거 VI 이력 조회 API가 존재하는지 확인하는 것입니다.

**우선순위: 상위(P1)**. C3/CHARLIE-VI 없이도 나머지 6개 엔진은 작동 가능하나, 기대값이 가장 높은 전략(EV +3.2%)이므로 확보가 중요합니다.

### 2.4 수급 데이터 (외국인·기관 매매동향)

현재 상태: v4_investor_trading 또는 유사 테이블 확인 필요합니다.

필요 항목은 ticker, date(일별) 또는 datetime(분별), foreign_buy/sell/net(외국인 매수/매도/순매수), institution_buy/sell/net(기관 매수/매도/순매수), individual_buy/sell/net(개인 매수/매도/순매수), foreign_holding_ratio(외국인 보유 비율)입니다.

용도는 다음과 같습니다. C1(갭)에서 체결 강도 대용지표로 활용됩니다. C4(VWAP)에서 수급 전환 확인에 사용됩니다. C6(업종 후발)에서 대장주·후발주 수급 비교에 활용됩니다. C7(과매도)에서 외·기관 순매수 전환 감지에 사용됩니다. FOXTROT-SECTOR, GOLF-REVERSAL 전략의 CS 계산에 수급 항목이 포함되어 있습니다.

데이터 구분이 중요합니다. 일별 수급 데이터와 분별(또는 시간별) 수급 데이터는 용도가 다릅니다. 일별 데이터는 일봉 기반 필터링과 사후 분석에 사용되고, 분별 데이터는 장중 실시간 수급 전환 감지에 사용됩니다. 분별 수급 데이터가 없으면 일별 데이터로 대체하되, C4·C7의 "장중 순매수 전환" 판단 정밀도가 떨어집니다.

**우선순위: 상위(P1)**. 4개 Condition과 4개 Strategy에 직접 영향을 줍니다.

### 2.5 업종(섹터) 데이터

현재 상태: v4_sector_price 테이블이 정의되어 있으나 활성화 여부 확인 필요합니다.

필요 항목은 sector_code(업종 코드), sector_name(업종명), date 또는 datetime, open/high/low/close, volume, value, top_stocks(업종 내 시총 상위 종목 리스트)입니다. 추가로 종목-업종 매핑 테이블이 필요합니다. ticker, sector_code, market_cap_rank(업종 내 시총 순위)를 포함해야 합니다.

용도는 다음과 같습니다. C6(업종 후발)의 핵심 데이터로, 대장주 급등 감지와 후발주 선별에 사용됩니다. FOXTROT-SECTOR 전략의 상관계수 계산(종목-대장주 60일 상관)에 필요합니다. 적합도 매트릭스의 레짐 판단 보조 지표로 활용됩니다.

확보 방안은 KRX 업종 분류 체계(GICS 또는 KRX 자체 분류)를 기반으로 종목-업종 매핑을 구축하고, 업종별 일봉·분봉 지수를 구성(소속 종목 시총 가중 평균)하는 것입니다.

**우선순위: 상위(P1)**. C6/FOXTROT-SECTOR가 이 데이터 없이는 완전히 비활성화됩니다.

### 2.6 호가(Orderbook) 이력 데이터

현재 상태: 실시간 데이터로만 계획되어 있으며, 과거 이력은 미확보 상태일 가능성이 높습니다.

필요 항목은 ticker, datetime, bid_price_1~10(매수 호가 1~10단계), bid_volume_1~10, ask_price_1~10(매도 호가 1~10단계), ask_volume_1~10, spread(매수1호가-매도1호가 차이), buy_ratio(매수잔량 비율)입니다.

용도는 다음과 같습니다. C1(갭)에서 스프레드 점수 산정에 사용됩니다. C3(VI)에서 VI 해제 후 호가 매수 편향 판단에 사용됩니다. CHARLIE-VI의 CS 중 호가 편향 항목(15점)에 직접 영향을 줍니다. TIER 4~5의 슬리피지 예측에 활용됩니다.

현실적 판단이 필요합니다. 호가 이력 데이터는 용량이 방대하고(종목당 하루 수만 건의 호가 스냅샷), 확보가 매우 어렵습니다. 백테스트에서는 호가 관련 점수 항목을 제외하거나 분봉 데이터에서 추정치로 대체하는 방안이 현실적입니다. 구체적으로, 스프레드는 일봉의 시가·고가·저가·종가로부터 평균 스프레드를 추정(Corwin-Schultz 방법)할 수 있고, 매수 편향은 체결 강도(틱 데이터 기반)로 대체할 수 있습니다.

**우선순위: 하위(P3)**. 백테스트에서는 대체 가능하며, 실시간 운영 시에만 필수입니다.

### 2.7 뉴스·공시 이력 데이터

현재 상태: 미확보 가능성 높습니다.

필요 항목은 ticker(해당 종목), datetime(발표 시각), headline(제목), source(출처: DART/뉴스사), category(실적/수주/M&A/규제/테마/기타), sentiment(긍정/중립/부정, 가능 시)입니다.

용도는 다음과 같습니다. C1(갭)에서 갭의 원인 판별(뉴스 존재 시 DESK 점수 +20점)에 사용됩니다. C7(과매도)에서 악재 뉴스 필터(악재 존재 시 진입 금지)에 사용됩니다. GOLF-REVERSAL의 CS 중 뉴스 필터 항목(20점)에 직접 영향을 줍니다.

확보 방안은 세 가지입니다. 방안 A는 DART(전자공시시스템) API로 과거 공시 데이터를 수집하는 것입니다. 방안 B는 뉴스 API(네이버 금융, 한경 등)로 종목별 과거 뉴스를 수집하는 것입니다. 방안 C는 백테스트에서 뉴스 항목을 제외하고, 실시간 운영 시에만 활성화하는 것입니다.

현실적 판단이 필요합니다. 과거 뉴스 데이터를 정확한 타임스탬프와 종목 매핑으로 확보하는 것은 상당한 노력이 필요합니다. 백테스트 Phase 1~2에서는 뉴스 항목을 제외(해당 점수 항목을 0으로 처리)하고, Phase 5(Mock Trading)에서 실시간 뉴스를 투입하여 효과를 측정하는 순차적 접근이 합리적입니다.

**우선순위: 중위(P2)**. 백테스트 초기에는 없어도 진행 가능하나, 정밀도 향상을 위해 중기적으로 확보해야 합니다.

### 2.8 체결 강도 데이터

현재 상태: 별도 테이블 확인 필요합니다.

필요 항목은 ticker, datetime(분별 또는 틱별), buy_volume(매수 체결량), sell_volume(매도 체결량), intensity(매수체결량 ÷ 매도체결량 × 100)입니다.

용도는 다음과 같습니다. C1(갭)의 DESK 점수 중 체결 강도 항목(20점)에 사용됩니다. C3(VI)에서 VI 해제 후 체결 강도 ≥ 150% 진입 조건에 사용됩니다. ALPHA-GAP의 CS 중 체결 강도 항목(20점), CHARLIE-VI의 CS 중 체결 강도 항목(25점)에 직접 영향을 줍니다.

확보 방안은 두 가지입니다. 방안 A는 틱 데이터에서 매수·매도 체결을 구분하여 집계하는 것입니다(틱 데이터가 있는 경우). 방안 B는 분봉 데이터에서 체결 강도를 추정하는 것으로, 종가 > 시가이면 매수 우위, 종가 < 시가이면 매도 우위로 간주하고, 거래량을 상승/하락 봉에 따라 배분하는 방법입니다. 정확도는 70~80% 수준입니다.

**우선순위: 상위(P1)**. C1·C3와 ALPHA·CHARLIE 전략의 핵심 입력값이며, 분봉으로 추정 가능하므로 확보 난이도는 중간입니다.

### 2.9 상관계수 매트릭스

현재 상태: 사전 계산이 필요한 파생 데이터입니다.

필요 항목은 ticker_a, ticker_b, period(60일), correlation(피어슨 상관계수), sector_code입니다.

용도는 C6(업종 후발)에서 대장주-후발주 상관계수 ≥ 0.7 필터에 사용됩니다.

산출 방법은 일봉 종가 기준 60일 롤링 상관계수를 계산하는 것이며, 동일 업종 내 종목 쌍에 대해서만 계산하면 연산량을 크게 줄일 수 있습니다. 업종당 10개 종목이면 업종당 45쌍, 30개 업종이면 1,350쌍으로 관리 가능합니다.

생성 조건은 일봉 데이터(2.2)와 업종 데이터(2.5)가 확보된 후 자동 생성 가능합니다.

**우선순위: 파생 데이터** — 일봉+업종 확보 후 자동 산출됩니다.

## Part 3. 실시간 운영용 데이터

### 3.1 실시간 체결(Tick) 스트림

데이터 소스는 KIS OpenAPI WebSocket(실시간 체결 통보)입니다.

수신 항목은 ticker, price(체결가), volume(체결량), timestamp(체결 시각), side(매수/매도 구분, API 지원 시)입니다.

용도는 Layer 0의 TickCollector가 수신하여 BarBuilder, IndicatorEngine에 공급하는 것입니다. 모든 Condition과 Strategy의 실시간 판단 기반이 됩니다.

현재 상태는 KIS OpenAPI WebSocket 연동이 구현되어 있는지 확인이 필요합니다. 기존 v4.1 시스템에서 실시간 시세 수신 모듈이 있을 것으로 예상되며, DESK 2 Layer 0에 맞게 인터페이스를 조정하면 됩니다.

기술 요구사항은 종목당 초당 최대 100건 처리, 전체 감시 종목 500~1,000개 동시 구독, 지연 < 50ms(네트워크 포함)입니다.

**우선순위: 최우선(P0)**. 실시간 운영의 기본입니다.

### 3.2 실시간 호가(Orderbook) 스트림

데이터 소스는 KIS OpenAPI WebSocket(실시간 호가 통보)입니다.

수신 항목은 ticker, bid_price_1~10, bid_volume_1~10, ask_price_1~10, ask_volume_1~10, timestamp입니다.

용도는 Layer 0의 OrderBookCollector가 수신하여 스프레드, 매수 비율을 계산하는 것입니다. C1(스프레드 점수), C3(호가 매수 편향), TIER 4~5 슬리피지 판단에 사용됩니다.

현재 상태는 v4_orderbook_realtime이 계획되어 있으나 활성화 여부 확인이 필요합니다.

기술 요구사항은 500ms 간격 갱신, 감시 종목 전체 대상입니다.

**우선순위: 상위(P1)**. C1·C3의 정밀도에 직접 영향을 줍니다.

### 3.3 실시간 뉴스·공시 피드

데이터 소스 후보는 DART Open API(공시), 한국경제/매일경제/네이버금융 뉴스 API, 증권사 제공 뉴스 피드(KIS 제공 여부 확인 필요)입니다.

수신 항목은 ticker(해당 종목), datetime(발표 시각), headline(제목), source(출처), category(분류)입니다.

용도는 C1(갭)에서 뉴스 존재 여부로 DESK 점수에 가산하는 것이고, C7(과매도)에서 악재 뉴스 필터로 진입을 차단하는 것입니다. ALPHA-GAP, GOLF-REVERSAL의 CS 계산에 영향을 줍니다.

현재 상태는 미구현 가능성이 높습니다.

기술 요구사항은 발표 후 30초 이내 수신, 종목 코드 자동 태깅(공시는 DART에서 종목코드 제공, 뉴스는 NLP 또는 규칙 기반 태깅 필요)입니다.

**우선순위: 중위(P2)**. 없이도 운영 가능하나(해당 점수 항목 비활성화), 중기적으로 확보하면 C1의 DESK 점수 정밀도가 약 20% 향상됩니다.

### 3.4 실시간 VI 발동·해제 알림

데이터 소스는 KIS OpenAPI(VI 발동/해제 실시간 통보 API 존재 여부 확인 필요) 또는 실시간 체결 스트림에서 VI 발동을 감지(일정 시간 체결 없음 + 직전 급등/급락 패턴)하는 방법입니다.

수신 항목은 ticker, vi_trigger_time, vi_type(동적/정적, 상한/하한), trigger_price, expected_release_time입니다.

용도는 C3(VI 폭발)의 실시간 트리거입니다. VI 발동 즉시 Condition 3이 활성화되고, 해제 시 CHARLIE-VI가 진입을 판단합니다.

확보 방안은 두 가지입니다. 방안 A는 KIS OpenAPI에 VI 전용 실시간 통보 채널이 있는지 확인하는 것입니다. 방안 B는 실시간 체결 스트림에서 VI를 자체 감지하는 것으로, 특정 종목의 체결이 갑자기 중단(2분 이상 체결 없음)되고 직전 1분 변동이 ±3% 이상이면 VI 발동으로 추정합니다. 체결 재개 시 VI 해제로 판단합니다.

**우선순위: 상위(P1)**. C3/CHARLIE-VI(기대값 최고 전략 EV +3.2%)의 핵심 트리거입니다.

### 3.5 실시간 수급 데이터 (외국인·기관 장중 매매)

데이터 소스는 KIS OpenAPI(종목별 투자자 매매동향 실시간 조회)입니다.

수신 항목은 ticker, datetime, foreign_net(외국인 순매수), institution_net(기관 순매수), individual_net(개인 순매수)입니다.

용도는 C4(VWAP)에서 장중 순매수 전환 감지, C7(과매도)에서 외·기관 순매수 전환 확인에 사용됩니다. DELTA-VWAP, GOLF-REVERSAL의 CS 중 수급 항목 산정에 활용됩니다.

갱신 주기는 1분 또는 5분 간격입니다(API 제한에 따라 조정).

**우선순위: 상위(P1)**. 4개 Condition/Strategy에 영향을 줍니다.

### 3.6 실시간 업종 지수

데이터 소스는 KIS OpenAPI(업종별 지수 실시간 조회) 또는 KRX 업종 지수입니다.

수신 항목은 sector_code, datetime, price(업종 지수), change_pct(등락률), volume(업종 거래량)입니다.

용도는 C6(업종 후발)에서 대장주 급등 시 업종 전체 동향 확인, 레짐 판단(시장 전체 방향)에 사용됩니다.

**우선순위: 상위(P1)**. C6/FOXTROT-SECTOR의 실시간 작동에 필수입니다.

### 3.7 실시간 시장 지수 (KOSPI/KOSDAQ/VKOSPI)

데이터 소스는 KIS OpenAPI(지수 실시간 시세)입니다.

수신 항목은 index_code(KOSPI/KOSDAQ/VKOSPI), datetime, price, change_pct, volume입니다.

용도는 레짐 판단(상승/하락/횡보/고변동)의 핵심 입력이며, C2(ORB)에서 시장 방향 동조 점수, C7(과매도)에서 시장 동반 하락 확인, Soft Kill 규칙(VKOSPI > 25 시 포지션 축소)에 사용됩니다.

**우선순위: 최우선(P0)**. 레짐 판단 없이는 Orchestrator가 작동하지 않습니다.

## Part 6. 데이터 확보 실행 계획

### Phase A: 즉시 확인 및 기존 데이터 감사 (Day 1~2)

P0 확인사항 4건을 즉시 처리합니다. DB 스키마 전체 조회로 기존 테이블 목록을 확보합니다. 각 테이블의 행 수, 기간, 종목 수를 집계합니다. KIS OpenAPI 사용 가능 기능 목록을 정리합니다.

### Phase B: 부족 데이터 수집 (Day 3~7)

분봉 데이터가 부족한 경우 KIS OpenAPI 과거 분봉 조회로 보충합니다(API 제한: 1회 100건, 종목당 약 30초 소요, 1,000종목 × 2년 = 상당 시간 필요). 일봉 데이터가 부족한 경우 KIS OpenAPI 일봉 조회 또는 KRX 정보데이터시스템에서 다운로드합니다. 수급 데이터를 KIS API 또는 KRX에서 수집합니다. 업종 데이터를 구성합니다(KRX 업종 분류 + 업종 지수).

### Phase C: 파생 데이터 생성 (Day 7~10)

분봉에서 VWAP, RVOL, RSI, 볼린저밴드, ATR, MA를 사전 계산합니다. 분봉에서 체결 강도를 추정합니다. 일봉에서 상관계수 매트릭스를 산출합니다. 분봉에서 VI 이력을 역추정합니다.

### Phase D: 실시간 파이프라인 구축 (Day 10~15)

KIS WebSocket 체결·호가 수신 모듈을 Layer 0에 연결합니다. 시장 지수·업종 지수 실시간 수신을 구현합니다. VI 감지 로직을 구현합니다(API 또는 자체 감지). 수급 실시간 조회를 구현합니다(폴링 방식).

### Phase E: 뉴스 파이프라인 (Day 15~20)

DART 공시 실시간 수신을 구현합니다. 뉴스 API 연동을 구현합니다(가능 시).

## Part 7. 데이터 없이 시작 가능한 범위

모든 데이터가 완벽히 확보되기를 기다리면 구현이 지연됩니다. 현재 확보된 분봉 데이터(v4_minute_bar)만으로도 시작할 수 있는 범위가 있습니다.

분봉만으로 백테스트 가능한 Condition/Strategy는 C2(ORB)/BRAVO-ORB(레인지 돌파, 분봉만으로 완전 재현 가능), C5(눌림목)/ECHO-ABCD(A→B→C 패턴, 분봉으로 탐지 가능)입니다.

분봉 + 일봉으로 백테스트 가능한 항목은 C1(갭)/ALPHA-GAP(전일 종가 필요 → 일봉, 장중 패턴 → 분봉), C4(VWAP)/DELTA-VWAP(VWAP 계산 → 분봉, RVOL 기준값 → 일봉)입니다.

추가 데이터 필요한 항목은 C3(VI)/CHARLIE-VI(VI 이력 필요), C6(업종 후발)/FOXTROT-SECTOR(업종 데이터 필요), C7(과매도)/GOLF-REVERSAL(수급 데이터 필요)입니다.

따라서, Phase A 확인이 끝나면 최소 C2/BRAVO-ORB와 C5/ECHO-ABCD의 백테스트를 즉시 시작할 수 있으며, 일봉이 확보되면 C1/ALPHA-GAP과 C4/DELTA-VWAP도 추가됩니다. 나머지 3개는 데이터 확보 진행과 병렬로 구현하되 백테스트는 데이터 확보 후 실행합니다.
