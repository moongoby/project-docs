## 1. 확인 결과

### 1.1 DB 분봉 현황 (수정 전 기준)

| 거래일     | 요일 | v4_ohlcv_minute 행 수 | 종목 수 | 비고       |
|-----------|------|------------------------|--------|------------|
| 2026-02-19 | 목   | 189,204                | 500    | 정상 수집  |
| 2026-02-20 | 금   | 72,904                 | 193    | **일부만 수집** |
| 2026-02-21 | 토   | -                      | -      | 휴장일(수집 대상 아님) |
| 2026-02-23 | 월   | 0                      | 0      | **미수집** |
| 2026-02-24 | 화   | 0                      | 0      | **미수집** |

### 1.2 원인

- **거래일 목록 출처**: `collector_minute.py`의 `_get_trading_dates()`가 **ohlcv_daily** 테이블(005930 기준 DISTINCT date)만 사용.
- **ohlcv_daily 최근 일자**: `20260223`, `20260220`, `20260219`, … → **20260224(당일) 없음**, 20260221은 휴장일이라 없음.
- 결과:
  1. **당일(02-24)** 이 ohlcv_daily에 없어 분봉 수집 대상에 포함되지 않음.
  2. **전일(02-23)** 은 ohlcv_daily에 있으나, 수집기가 해당 일자를 대상으로 돌기 전에 중단되었거나, 당일이 목록에 없어 장중 수집 흐름이 달랐을 수 있음.  
     → 어쨌든 **당일을 목록에 보강하지 않으면** 장중/당일 분봉이 영구적으로 빠질 수 있음.
  3. **금요일(02-20) 일부만 수집**: 193종목만 수집된 상태로, 나머지 종목은 resume 시 이어서 수집 가능.

## 2. 수정 내용

**파일**: `backend/app/services/data_pipeline/collector_minute.py`

### 2.1 추가 함수: `_recent_weekdays_yyyymmdd(calendar_days=14)`

- **역할**: 한국 거래일 보강용.
- **로직**: KST 기준 “오늘”부터 과거 14일 중 **평일(월~금)** 만 골라 `YYYYMMDD` 리스트로 반환.
- **용도**: ohlcv_daily에 없는 **당일·전일** 등이 분봉 수집 대상에서 빠지지 않도록 보강.

### 2.2 변경: `_get_trading_dates(days)`

- **기존**: ohlcv_daily에서만 거래일 조회 → 당일/전일 누락 가능.
- **변경**:
  - ohlcv_daily에서 조회한 거래일을 `YYYYMMDD`로 통일.
  - 위 `_recent_weekdays_yyyymmdd(14)` 결과와 **합집합** 후, 최신일 우선 정렬하여 반환.
  - 보강으로 추가된 일자가 있으면 로그 출력:  
    `거래일 보강 적용: ohlcv_daily N일 + 평일 보강 → 합계 M일 (추가: [...])`

### 2.3 효과

- **당일(02-24)** · **전일(02-23)** 이 ohlcv_daily 유무와 관계없이 거래일 목록에 포함됨.
- **금요일(02-20)** 은 원래 ohlcv_daily에 있으므로 그대로 대상이며, **resume=True** 시 이미 수집된 193종목은 스킵하고 나머지 종목만 이어서 수집됨.
- 휴장일(예: 2026-02-21 토요일)은 `weekday() < 5` 조건으로 보강 리스트에 들어오지 않음.

## 3. 조치 방법 (수집 실행)

### 3.1 systemd 서비스로 상시 수집 중인 경우

- 수정 반영 후 서비스 재시작 시, 다음 주기부터 **02-23, 02-24**가 자동으로 대상에 포함됨.
- 재시작 예시:
  ```bash
  sudo systemctl restart kis-v41-minute-collector
  ```

### 3.2 수동 1회 실행

- 프로젝트 루트에서:
  ```bash
  cd /root/kis-autotrade-v4 && . .venv/bin/activate
  python -m backend.app.services.data_pipeline.collector_minute --days 30
  ```
- `--no-resume` 없이 실행하면 이미 수집된 (종목, 날짜)는 스킵되고, **02-20 미수집 종목·02-23·02-24** 등만 추가 수집됨.

### 3.3 검증

- 수집 후 아래처럼 날짜별 건수 확인:
  ```sql
  SELECT trade_date, COUNT(*) AS rows, COUNT(DISTINCT stock_code) AS tickers
  FROM v4_ohlcv_minute
  WHERE trade_date >= CURRENT_DATE - 7
  GROUP BY trade_date ORDER BY trade_date DESC;
  ```
- 또는 API: `GET /api/v4/data/ohlcv-status?days=7`
