# 관리자 데이터 수집 — 기간 조회·일자별 항목별 수집 현황 화면 기획

**작성일**: 2026-02-24  
**관련 문서**: [ADMIN-DATA-COLLECTION-PLAN-ADDENDUM-20260224.md](./ADMIN-DATA-COLLECTION-PLAN-ADDENDUM-20260224.md), [DATA-LIFECYCLE-IMPROVEMENT-PLAN-20260224.md](./DATA-LIFECYCLE-IMPROVEMENT-PLAN-20260224.md)  
**목적**: 기간 조회 시 **일자별·항목별** 수집 현황을 표로 보여 주고, **전체 수집 대상 대비 얼마나 수집되었는지**(수집률)를 한 화면에서 파악할 수 있도록 화면을 기획한다.

---

## 1. 화면 목표

- **기간 선택** → [조회] 시, 해당 기간 내 **거래일별**로 **각 수집 항목**의 다음을 표시한다.
  - **수집된 건수(또는 종목 수)**
  - **전체 수집 대상 수** (항목별 정의)
  - **수집률** (수집 / 대상 × 100%)
  - **상태** (정상 / 부분 / 미수집)
- 관리자가 “전체 수집 대상 중 얼마나 수집되었는지”를 **일자·항목** 단위로 한눈에 확인할 수 있도록 한다.

---

## 2. “전체 수집 대상” 정의 (항목별)

수집률 계산을 위해, 항목별로 **해당 일자의 이론적 전체 대상**을 아래와 같이 정의한다.

| 항목 | 테이블 | 전체 수집 대상 정의 | 단위 | 비고 |
|------|--------|----------------------|------|------|
| 일봉 | ohlcv_daily | 해당 시점 **유니버스 활성 종목 수** | 종목 수 | 당일 유니버스는 “현재” is_active count 사용 가능. 과거일은 당시 스냅 없으면 현재 유니버스 수로 근사 |
| 분봉 | v4_ohlcv_minute | **대상 종목 수 × 1일 봉 수** | 건수 | 대상 종목: 예 500종목. 1일 봉 수: 장중 390봉(09:00~15:30, 1분봉). 대상 ≈ 500 × 390 = 195,000 (설정값으로 조정 가능) |
| 종목별 수급 | v4_investor_daily | 해당 시점 **유니버스 활성 종목 수** | 종목 수 | 일봉과 동일 |
| 시장 수급 | v4_market_investor_daily | **1** (일자당 1건) 또는 고정 행 수 | 건수 | 일자당 1행 기준이면 target=1 |
| 지수 일봉 | index_daily | **지수 개수** (고정, 예: 3~10) | 건수 | 수집 대상 지수 개수 |
| 시장 레짐 | v4_market_regime_daily | **1** (일자당 1건) | 건수 | |
| 섹터 일봉 | v4_sector_daily | **업종 코드 개수** (고정, SECTOR_CODES 수) | 건수 | 예: 20~30개 업종 |
| 순위 | v4_market_ranking | **순위 타입별 건수** (예: 타입당 50×2시장 = 100) | 건수 | 타입·시장별 상위 N건 합계 |
| 호가 실시간 | v4_orderbook_realtime | (선택) 장중만 사용 시 “해당 일자 건수 기대치” 또는 미표시 | 건수 | 정책에 따라 생략 가능 |
| 유니버스 | stock_universe | — | — | 일자별이 아닌 “현재 활성 종목 수”만 표시하는 블록에서 처리 |

- **백엔드**: 위 정의에 따라 항목·일자별로 **target** 값을 계산하거나 설정 테이블/상수로 두고, **수집 건수 / target** 로 수집률을 산출한다.
- **target을 구할 수 없는 항목**은 “수집 건수”만 표시하고 수집률은 “—” 또는 “N/A”로 둘 수 있다.

## 3. API 스펙 (기간 조회)

### 3.1 엔드포인트

```
GET /api/v4/admin/data-collection/by-date?from=2026-02-01&to=2026-02-24
```

- **권한**: 관리자 전용 (`get_current_admin_user` 또는 `verify_admin`).
- **쿼리**: `from`, `to` (YYYY-MM-DD), (선택) `exclude_weekends=true`.

### 3.2 응답 스키마 (일자별·항목별 + 수집률)

각 **일자**마다, 각 **항목**마다 **수집 건수**, **전체 대상**, **수집률**, **상태**를 내려준다.

```json
{
  "from": "2026-02-01",
  "to": "2026-02-24",
  "exclude_weekends": true,
  "trading_dates": ["2026-02-24", "2026-02-23", "2026-02-20", "2026-02-19", "..."],
  "targets": {
    "ohlcv_daily": 3844,
    "v4_ohlcv_minute": 195000,
    "v4_investor_daily": 3844,
    "v4_market_investor_daily": 1,
    "v4_sector_daily": 28,
    "v4_market_ranking": 100
  },
  "rows": [
    {
      "date": "2026-02-24",
      "weekday": "화",
      "items": {
        "ohlcv_daily": {
          "collected": 0,
          "target": 3844,
          "pct": 0,
          "status": "missing"
        },
        "v4_ohlcv_minute": {
          "collected": 0,
          "target": 195000,
          "pct": 0,
          "status": "missing"
        },
        "v4_investor_daily": {
          "collected": 0,
          "target": 3844,
          "pct": 0,
          "status": "missing"
        },
        "v4_sector_daily": { "collected": 28, "target": 28, "pct": 100, "status": "ok" },
        "v4_market_ranking": { "collected": 0, "target": 100, "pct": 0, "status": "missing" }
      }
    },
    {
      "date": "2026-02-23",
      "weekday": "월",
      "items": {
        "ohlcv_daily": { "collected": 3844, "target": 3844, "pct": 100, "status": "ok" },
        "v4_ohlcv_minute": { "collected": 67695, "target": 195000, "pct": 35, "status": "partial" },
        "v4_investor_daily": { "collected": 0, "target": 3844, "pct": 0, "status": "missing" },
        "v4_sector_daily": { "collected": 28, "target": 28, "pct": 100, "status": "ok" },
        "v4_market_ranking": { "collected": 100, "target": 100, "pct": 100, "status": "ok" }
      }
    }
  ],
  "summary": {
    "by_item": {
      "ohlcv_daily": { "days_ok": 12, "days_partial": 0, "days_missing": 2, "total_days": 14 },
      "v4_ohlcv_minute": { "days_ok": 5, "days_partial": 7, "days_missing": 2, "total_days": 14 }
    }
  }
}
```

- **targets**: 기간/현재 기준으로 쓰인 **항목별 전체 대상 수** (화면 상단 요약·툴팁에 사용 가능).
- **rows[].items**: 일자별로 각 항목의 `collected`, `target`, `pct`, `status`.
- **status**: `ok`(수집률 충족), `partial`(일부 수집), `missing`(미수집). 기준은 정책에 따라 (예: pct ≥ 95% → ok, 0 < pct < 95% → partial, 0 → missing).
- **summary.by_item**: 기간 내 “전체 거래일 중 정상/부분/미수집 일수”를 항목별로 요약. 화면에 “기간 내 수집 완료율” 표시용.

## 4. 화면 구성 (UI 기획)

### 4.1 레이아웃 개요

- **위치**: 관리자 **데이터 수집** 탭 내, “실시간 수집 현황” 블록 아래 또는 별도 섹션 **“기간별 일자·항목 수집 현황”**.
- **구성 요소**:
  1. **기간 선택 + 조회**
  2. **기간 요약 카드** (전체 수집 대상 대비 기간 내 수집률)
  3. **일자별·항목별 수집 현황 표**
  4. (선택) **항목별 요약** (기간 내 정상/부분/미수집 일수)

### 4.2 블록 1: 기간 선택 및 조회

| 요소 | 설명 |
|------|------|
| 시작일 | DatePicker, 기본값: 오늘 기준 14일 전 |
| 종료일 | DatePicker, 기본값: 오늘 |
| 휴장일 제외 | 체크박스, 기본 체크 (토·일 제외) |
| [조회] 버튼 | 클릭 시 `GET .../by-date?from=&to=` 호출 후 하단 표·요약 갱신 |
| (선택) 빠른 선택 | “최근 7일”, “최근 14일”, “최근 30일” 버튼 |

### 4.3 블록 2: 기간 요약 카드

- **목적**: “이 기간 전체에서, 전체 수집 대상 중 얼마나 수집되었는지” 요약.
- **표시 예**:
  - **일봉**: 기간 내 14거래일 중 13일 100% 수집 → **92.9% 일수 충족**
  - **분봉**: 14일 중 5일 100%, 7일 부분 수집 → **35.7% 완전 충족**, **85.7% 1건 이상 수집**
  - (동일 패턴으로 섹터·순위·수급 등)
- **시각**: 카드 그리드 또는 컴팩트 테이블. 항목명 | 기간 거래일 수 | 100% 일수 | 부분 일수 | 미수집 일수 | “기간 수집 충족률” 등.

### 4.4 블록 3: 일자별·항목별 수집 현황 표

- **행**: 기간 내 **거래일** (일자 내림차순). 각 행에 **일자**, **요일** 표시.
- **열**: **수집 항목** (일봉, 분봉, 수급, 시장수급, 섹터, 순위, …). 1차는 일봉·분봉·수급·섹터·순위 위주, 필요 시 시장수급·지수·레짐 확장.
- **셀 내용**:
  - **수집 / 전체** (예: `3,844 / 3,844`)
  - **수집률** (예: `100%`). 툴팁 또는 서브 텍스트로 표시.
  - **상태 뱃지**: 정상(녹색), 부분(노랑), 미수집(빨강/회색).
- **가독성**:
  - 수집률 100%: 녹색 또는 체크 아이콘.
  - 부분: 노란 뱃지 + 툴팁 “목표 대비 n%”.
  - 미수집: “0 / 3,844 (0%)” + 미수집 뱃지.
- **반응형**: 가로 스크롤 또는 열 접기(항목 그룹)로 모바일 대응.

### 4.5 블록 4 (선택): 항목별 요약

- **목적**: “기간 내 해당 항목이 며칠 완전 수집·부분·미수집이었는지” 한 줄로 요약.
- **표시**: 항목명 | 전체 거래일 수 | 정상 일수 | 부분 일수 | 미수집 일수 | 비고(예: “2일 미수집 → [수집] 버튼 권장”).

## 5. 백엔드 구현 포인트

- **거래일 목록**: from~to 사이에서 토·일 제외한 날짜 리스트 생성.
- **항목별 집계**:
  - 일봉: `SELECT date, COUNT(DISTINCT stock_code) FROM ohlcv_daily WHERE date BETWEEN ... GROUP BY date`
  - 분봉: `SELECT trade_date, COUNT(*) FROM v4_ohlcv_minute WHERE trade_date BETWEEN ... GROUP BY trade_date`
  - 수급·섹터·순위 등: 해당 테이블의 date/trade_date 컬럼으로 `GROUP BY` 후 건수 조회.
- **target 계산**:
  - 일봉/수급: `SELECT COUNT(*) FROM stock_universe WHERE is_active = true` (현재 값으로 통일 가능).
  - 분봉: 상수 또는 설정값 (예: 500 × 390 = 195,000).
  - 섹터: SECTOR_CODES 길이, 순위: 타입별 상위 N건 × 시장 수 등.
- **status 판정**: `pct >= 95` → ok, `0 < pct < 95` → partial, `pct == 0` (또는 collected==0) → missing. 기준값은 설정 가능하게 두는 것을 권장.
- **summary.by_item**: rows를 순회하여 항목별로 status 개수 집계.

## 6. 정리

- **기간 조회** 시 **일자별·항목별**로 **수집 건수**, **전체 수집 대상**, **수집률**, **상태**를 표로 제공한다.
- **전체 수집 대상**은 항목별로 정의(유니버스 종목 수, 분봉은 종목×봉 수 등)하고, API에서 `target`과 `pct`를 함께 내려준다.
- **화면**은 (1) 기간 선택·조회, (2) 기간 요약 카드, (3) 일자×항목 표, (4) 항목별 요약으로 구성하여 “전체 수집 대상 중 얼마나 수집되었는지”를 한 화면에서 확인·관리할 수 있도록 한다.
