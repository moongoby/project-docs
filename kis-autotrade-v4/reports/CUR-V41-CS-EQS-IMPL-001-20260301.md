### 16-A: conviction_score.py

```python
@dataclass
class CSResult:
    total_score: int                  # 0~100
    daily_grade_score: int            # 0~25
    match_quality_score: int          # 0~20
    time_fit_score: int               # 0~20
    tech_confirm_score: int           # 0~20
    market_env_score: int             # 0~15
    details: Dict

@dataclass
class CSJudgment:
    judgment: str    # FULL/REDUCED/BLOCKED
    multiplier: float  # 1.0/0.5/0.0
    score: int
    reason: str

class ConvictionScoreEngine:
    def calc_daily_grade(dcs_grade: str) -> int
    def calc_match_quality(trigger_id, tactic_id, matrix=None) -> int
    def calc_time_fit(strategy_id, current_time: str) -> int
    def calc_tech_confirm(signal_id, pf_ranking: int) -> int
    def calc_market_env(regime, volatility) -> int
    def calculate(context: Dict) -> CSResult
    def judge(cs_score: int) -> CSJudgment
```

**5요소 배점:**

| 요소 | 만점 | 기준 |
|------|------|------|
| DAILY_GRADE | 25 | A=25, B=20, C=15, D=10, F=0 |
| MATCH_QUALITY | 20 | OPTIMAL=20, SUITABLE=15, CONDITIONAL=8, FORBIDDEN=0 |
| TIME_FIT | 20 | PRIMARY=20, SECONDARY=14, NEUTRAL=8, OFF=0 |
| TECH_CONFIRM | 20 | TOP3=20, TOP5=16, TOP10=12, LOWER=8, NONE=0 |

### 16-B: execution_quality_score.py

```python
@dataclass
class EQSResult:
    total_score: int                   # 0~100
    slippage_est_score: int            # 0~20
    freshness_score: int               # 0~25
    vol_quality_score: int             # 0~20
    price_position_score: int          # 0~20
    orderbook_balance_score: int       # 0~15
    is_orderbook_proxy: bool
    details: Dict

@dataclass
class EQSGate:
    gate: str         # PROCEED/REDUCE/LIMIT_ONLY/REJECT
    multiplier: float
    slippage_penalty: float
    score: int
    reason: str

class ExecutionQualityScoreEngine:
    def calc_slippage_est(spread_pct, depth=0, surge_pct=0) -> int
    def calc_freshness(bars_since_signal: int) -> int
    def calc_vol_quality(current_vol, ma20_vol) -> int
    def calc_price_position(price, day_range, strategy_type='PULLBACK') -> int
    def calc_orderbook_balance(bid_vol=0, ask_vol=0, vp_ratio=1.0, use_proxy=False) -> int
    def calculate(context: Dict) -> EQSResult
    def judge(eqs_score: int) -> EQSGate
```

**ORDERBOOK_BALANCE 백테스트 프록시:**
> 백테스트에서는 실제 호가 데이터가 없으므로 VP_ratio를 프록시로 사용.
> `score = clip((VP_ratio - 1.0) × 15, 0, 15)`
> 실거래 배포 시 실제 bid_vol/ask_vol로 대체 필요.

**EQS 게이트:**
- ≥ 65: PROCEED (전체 실행, 추가 슬리피지 0%)
- 50~64: REDUCE (50% 축소, +0.05% 슬리피지)
- 35~49: LIMIT_ONLY (지정가만, +0.10% 슬리피지)
- < 35: REJECT (거부)

### 괴리 원인 분석

**CS 평균 66.9 vs 기대 78.1 (14.4% 괴리):**
1. DCS 등급 역산: 실제 DCS는 전략 카드별 별도 데이터 — pnl 기반 프록시 사용
2. 실제 D6(PF 13.63) 비중이 DB에서 낮아 고점수 케이스 부족
3. 시장 환경(regime) DB에서 부분적으로만 기록

**EQS 평균 67.8 — 기대 65.6 (3.3% ✅ 이내):**
- ORDERBOOK_BALANCE 프록시(VP_ratio) 방식이 실제값과 근접
- spread_pct → SLIPPAGE_EST 계산이 설계 의도와 잘 맞음

**CS≥65 PF 초과 원인:**
- pnl 기반 DCS 역산 시 수익 거래에 A등급 편향 → 고CS 집단이 이미 수익 거래
- 실제 DCS는 진입 시점 기준 (사전 정보) — 역산과 방향성 동일하나 원인 혼재
