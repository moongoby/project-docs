## §2. 구현 내용

### 2-1. app/sync/api_114_client.py (NAS → 114서버 HTTP 클라이언트)

| 메서드 | 기능 |
|--------|------|
| `healthcheck()` | GET /api/goods/healthcheck, bool 반환 |
| `get_images(goods_code)` | GET /api/goods/getImages/{code}, 이미지 정보 dict 반환 |
| `update_images(...)` | POST /api/goods/updateImages, GoodsSortImg1~4·GoodsEtc60~74 갱신 |
| `update_images_with_retry(...)` | 재시도 래퍼 (max_retries=2, retry_delay=3초) |

- 인증: X-API-Key 헤더 (config.api_114_key)
- dry_run=True 기본값 (안전 우선)
- 카테고리 → DB 필드 매핑 상수 `CATEGORY_FIELD_MAP` 정의

### 2-2. app/api/sync_router.py (FastAPI 라우터)

| 엔드포인트 | 메서드 | 설명 |
|-----------|--------|------|
| /api/v1/sync/healthcheck | GET | 114서버 API 생존 확인 |
| /api/v1/sync | POST | 단건 이미지 등록/갱신 |
| /api/v1/sync/batch | POST | 배치 이미지 등록/갱신 |
| /api/v1/sync/getImages/{goods_code} | GET | 상품 이미지 정보 조회 |

#### Goods.php 기능
- X-API-Key 헤더 인증 (`NAS_API_KEY` 환경변수)
- `healthcheck()` — HTTP 200 + JSON 응답
- `getImages($goods_code)` — goods_detail SELECT (GoodsSortImg1~4, GoodsEtc60~74)
- `updateImages()` — JSON body 파싱 → goods_detail UPDATE
  - dry_run=true: DB 미변경 (상품 존재 여부만 확인)
  - dry_run=false: 실제 UPDATE

## §5. 배포 절차 (114서버)

1. SSH 접속 가능한 환경에서 실행:
   ```bash
   NAS_API_KEY=<발급키> bash scripts/114_api/deploy_114_api.sh
   ```
2. 114서버 `.env` 또는 Apache/Nginx 환경변수에 `NAS_API_KEY` 설정
3. NAS Docker `.env`에 `API_114_KEY=<동일키>` 추가
4. healthcheck 확인:
   ```bash
   curl -H "X-API-Key: <key>" http://114.207.244.86/api/goods/healthcheck
   ```
