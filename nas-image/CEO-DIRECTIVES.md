## 1. 사고방식 원칙

### D-001 단순 사고 금지
- "하나를 던지면 10을 생각하고 연구해서 반영하라"
- 이미지 처리 하나를 하더라도 상세페이지 전환율, 브랜드 톤, 실무자 워크플로우까지 고려

### D-002 전환율이 곧 정답
- 모든 이미지 자동화의 최종 목표는 상세페이지 전환율 향상
- 예쁜 사진 ≠ 잘 팔리는 사진 — 상업적 매력도 우선

### D-003 자동화 범위 = 전 과정
- 촬영→분류→보정→크롭→인트로→리네임→업로드→DB등록 전체
- 최종 목표는 완전 자동, "반자동"은 과도기

### D-004 모델 보정은 미세하게
- 부자연스러우면 역효과
- 항목: 가슴/어깨/허리/엉덩이/다리길이/문신삭제/피부톤/턱선V
- 모델별 프리셋, 개별 항목 최대 10%

### D-005 인트로는 벤치마킹 기반
- 현재 뉴톡 수준 부족 — 아뜨랑스/프롬비기닝/난닝구 등 참고
- AI 도입 시 모든 상품에 인트로 적용
- 다양한 템플릿 (5종+)

### D-006 원본 보존 절대 원칙
- 어떤 과정에서도 원본 수정/삭제 금지
- 결과는 별도 폴더: _cropped → _toned → _retouched → _renamed

### D-007 모델사진 정렬 = 전환율 최적화
- 이쁜 사진 우선 → 다양한 컷 → 스타일링 → 디테일 순
- 전환율 높은 상세페이지 분석으로 지속 개선

### D-008 제품사진 정렬
- 색상별 누끼 → 전체 색상 사진 → 디테일컷 순

## 2. 기술적 지시

### T-001 파이프라인 단계
P1(폴더생성✅) → P2(OCR⏸) → P3(A컷✅) → P4-A(크롭) → P4-B(톤보정) → P4-C(체형보정) → P4-D(인트로) → P4-E(배포) → 114 API

### T-002 Docker 환경
- 컨테이너: newtalk-image-auto, 포트 8100
- /volume1/★제품사진/ → /data/photos/
- /volume1/★제품사진/_processed → /data/processed/
- DSM 스케줄러(root)로만 Docker 명령 실행

### T-003 Gemini API
- 호출 간 1초 딜레이
- PROHIBITED_CONTENT fallback 필수
- 대용량 timeout 1200초

### T-004 GoodsSortImg 정렬
- 1=인트로(2~4장), 2=모델(30~80장), 3=제품(10~20장), 4=관리 전체
- 구분자 ||
- URL: https://newtalk.nyc3.cdn.digitaloceanspaces.com/img/{YYYYMM}/{filename}

### T-005 114 서버 API
- POST /api/goods/updateImages, GET /api/goods/getImages/{code}
- X-API-Key 인증, 트랜잭션 필수

## 3. 절대 규칙 (위반 시 무효)
- 원본 이미지 수정/삭제 금지
- .env/API키 코드 하드코딩·커밋 금지
- Docker 내부에서 /volume1/ 직접 참조 금지
- 보정 강도 개별 10% 이내
- 작업 완료 시 HANDOVER.md 업데이트 필수
- 보고서 GitHub push + HTTP 200 확인 필수
- 114 DB UPDATE는 트랜잭션 필수
