## 1. 프로젝트 개요

### 1.1 배경
뉴톡(newtalk.kr)은 패션 이커머스 플랫폼으로, 매 시즌 수백~수천 장의 제품컷·모델컷 이미지를 촬영·보정·등록해야 한다. 현재 웹디자이너가 포토샵으로 수동 보정하고 114서버에 수동 업로드하는 12단계 프로세스가 병목이다.

### 1.2 목표
- 모델컷 보정 자동화 (포토샵 수동 보정 → 서버 자동 보정)
- 제품컷 배경제거 서버화 (아이폰 PhotoRoom 앱 → API 자동화, 현재는 앱 병행)
- 이미지 리사이즈·파일명 변환·114서버 동기화 자동화
- MD QC UI로 승인/반려 워크플로우 도입
- 레퍼런스 톤 매칭으로 촬영 세션 내 일관된 색감 유지

### 1.3 기대 효과
- 웹디자이너 수동 보정 시간 대폭 감소 (30장 기준 2-3시간 → 5분 QC)
- 이미지 품질 일관성 확보 (프리셋 기반 톤 매칭)
- 114서버 등록 자동화로 업로드 병목 해소

## 2. 현재 워크플로우 (AS-IS)

1단계: 샘플 입고
2단계: 아이폰 + PhotoRoom 앱으로 제품 촬영 (실시간 배경 제거)
3단계: 116서버 어드민에서 제품컷 등록용 폴더 생성
4단계: NAS에 원본·누끼 이미지 저장
5단계: 116서버 어드민에서 모델컷 코디 등록 → NAS 폴더 생성
6단계: 모델컷 촬영 (아이폰) → NAS 앱 연동 자동 등록
7단계: MD가 폴더 분류, A컷 선택
8단계: 114서버에 이미지 등록
9단계: 웹디자이너가 114서버에서 다운로드 후 포토샵 수동 보정
10단계: 보정된 이미지 114서버 재등록
11단계: 상세페이지 생성·저장
12단계: 상품 노출

### 핵심 병목
- 3곳의 수동 병목: MD A컷 분류, 웹디 다운로드·수동 보정, 재등록
- 이미지 분산: 원본·중간파일은 NAS, 최종파일은 114서버 → 동기화 수동

## 3. 자동화 후 워크플로우 (TO-BE)

1단계: 제품 촬영 (아이폰 원본 촬영, PhotoRoom 앱 병행)
2단계: 116서버에서 제품컷 폴더 생성
3단계: NAS에 원본 업로드
4단계: 116서버에서 모델컷 코디 등록 → NAS 폴더 생성
5단계: 모델컷 촬영 → NAS 자동 등록
6단계: EXIF 시간 기반 폴더 자동 분류 (코디별 그룹화, 임계값 180초)
7단계: NAS Docker 자동화 처리
  - 화이트밸런스 정규화 (선택)
  - 프리셋 기반 톤 매칭 (밝고 따뜻/밝고 차가움/자연스러운 중 선택)
  - 모델컷: 노출 보정 → CLAHE → 언샤프마스크 → AI 크랍 (전신/상반신/반신)
  - 제품컷: PhotoRoom API 배경제거 (rembg 폴백) → 누끼 PNG → 흰배경 JPEG
  - 리사이즈 (1200/600/300px)
  - 114서버 파일명 규칙 변환
8단계: MD QC UI (슬라이더 비교) – 원본/보정/레퍼런스 3장 비교, 승인/반려
9단계: 승인 → rsync로 114서버 자동 동기화
10단계: 자동 상세페이지 조합 (Phase 3)
11단계: 상품 노출

## 4. 핵심 기능 상세

### 4.1 이미지 보정 파이프라인
- 모델컷: EXIF 회전 → 화이트밸런스 정규화(선택) → 톤 프리셋 매칭 → 자동 노출(target_mean 135) → CLAHE(clipLimit 1.5, tileGrid 8×8) → 언샤프마스크(1.15/-0.15) → JPEG(quality 92)
- 제품컷: EXIF 회전 → PhotoRoom API(실패 시 rembg u2net) → 투명 PNG → 흰배경 JPEG(quality 92) + 300×300 썸네일(quality 85)

### 4.2 톤 매칭 시스템
- 프리셋 기반: 밝고 따뜻(A), 밝고 차가움(B), 자연스러운(C), 커스텀(D)
- LAB 색공간 분석: L/A/B 채널별 평균·표준편차, 색온도, 채도 추출
- 영역별 차등 매칭(예정): 의류(L 85%, A/B 20%), 피부(L 30%, A/B 10%), 배경(L 50%, A/B 0%)
- 피부톤 보호(예정): HSV 범위(H 0-50, S 40-200, V 80-255) 마스크
- 적응형 강도(예정): 원본-프리셋 거리 기반 자동 매칭 강도 조절
- 하이라이트/섀도우 보호: 상위/하위 5% 클램핑 (L 10-245)

### 4.3 AI 크랍 (MediaPipe Pose)
- 전신(full_body): 머리 위 15% 여백 ~ 발끝 아래 5% 여백
- 상반신(upper_body): 머리 ~ 허리(hip) 아래
- 반신(half_body): 머리 ~ 무릎(knee) 아래
- 포즈 미감지 시 고정 비율 폴백
- model_complexity=1 (NAS 하드웨어 고려)

### 4.4 폴더 자동 분류
- EXIF DateTimeOriginal 기반 시간순 정렬
- 인접 이미지 간 촬영 간격 계산, 180초 초과 시 새 코디 그룹
- QC UI에서 드래그앤드롭으로 수동 조정 가능

### 4.5 QC UI
- 좌우 슬라이더 비교 (원본 vs 보정본)
- 3장 비교 모드 (원본/레퍼런스/매칭결과)
- 크랍 미리보기 (전신/상반신/반신)
- 프리셋 선택 및 미리보기
- 승인/반려(사유 입력) + 세션 일괄 승인
- 모바일 반응형

### 4.6 114서버 동기화
- NAS _processed/{goods_code}/114/ → rsync → 114서버 goodscode/img/{code}/
- 파일명 변환: 제품컷 {code}_01.jpg, 모델컷 {code}-s_1.jpg, 리사이즈 {code}-600_1.jpg
- Phase 4: DB(goods_detail, goods_image) 자동 업데이트 + CDN 캐시 갱신

## 5. 톤 매칭 문제점 및 대응 방안

### 5.1 의류 색상 왜곡
- 문제: 전체 톤 매칭 시 의류 고유 색상 변질
- 대응: L채널 85% 매칭, A/B채널 20%로 색상 보호

### 5.2 피부톤 부자연
- 문제: 모델 피부톤이 프리셋에 맞춰져 인위적으로 변함
- 대응: HSV 기반 피부 마스크, 피부 영역 매칭 강도 30% 제한

### 5.3 배경 톤 불일치
- 문제: 자연광 촬영 시 배경 조명 변화
- 대응: 인물 영역과 배경 분리, 배경은 밝기만 50% 매칭

### 5.4 세션 내 급변 조명
- 문제: 같은 세션에서 시간에 따라 자연광 변화
- 대응: 이미지별 원본-프리셋 거리 계산 → 적응형 매칭 강도 자동 조정

### 5.5 디테일 손실
- 문제: 과도한 보정으로 하이라이트/섀도우 뭉침
- 대응: L채널 10-245 클램핑, 상위/하위 5% 구간 보호
