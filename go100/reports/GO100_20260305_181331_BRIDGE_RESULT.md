## 파트3: Nginx WS/SSE 감사

### /etc/nginx/sites-enabled/go100 내용
```nginx
upstream go100_backend {
    server 127.0.0.1:8002;
}

upstream go100_frontend {
    server 127.0.0.1:3000;
}

server {
    server_name go100.newtalk.kr;

    location /.well-known/acme-challenge/ {
        root /var/www/html;
    }

    # Next.js API routes — 프론트엔드 서버로 (FastAPI보다 먼저 매칭)
    location /api/go100/conversations {
        proxy_pass http://go100_frontend;
        proxy_set_header Host $host;
        ...
    }

    # API → 백엔드 (전체 타임아웃 300초)
    location /api/ {
        proxy_pass http://go100_backend;
        proxy_connect_timeout 30s;
        proxy_send_timeout 300s;
        proxy_read_timeout 300s;
    }

    location /docs { proxy_pass http://go100_backend; }
    location /redoc { proxy_pass http://go100_backend; }
    location /openapi.json { proxy_pass http://go100_backend; }
    location /health { proxy_pass http://go100_backend; }

    location /_next/static/ {
        proxy_pass http://go100_frontend;
        add_header Cache-Control "public, max-age=31536000, immutable";
    }

    location / {
        proxy_pass http://go100_frontend;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

### 분석 및 권고
- **SSE 2채널**: `/api/go100/notifications/stream`, `/api/v1/trading/dashboard/stream` → 8002 정상 라우팅, 401은 JWT 인증 필요 (정상)
- **/ws/ 라우트**: go100 nginx에 별도 /ws/ 블록 없음. `/` 경로에서 Upgrade 헤더 처리하여 go100_frontend(3000)로 전달
- **판단**: FE useWebSocket 훅이 WebSocket을 사용할 경우, 현재는 go100_frontend(3000)로 라우팅됨. 만약 go100 백엔드(8002)에 WebSocket 엔드포인트가 있다면 명시적 /ws/ 블록 추가 필요
- **현재 상태**: SSE는 8002로 정상, WS는 3000(Next.js)로 처리 중
