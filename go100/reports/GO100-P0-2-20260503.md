## 1. 문제 분석

### 증상
go100_orders 테이블에서 go100_card_id가 NULL인 주문이 다수 존재하여 어떤 전략카드가 어떤 주문을 생성했는지 추적 불가능한 상태

### 근본 원인

#### 1-1. go100_live_orders INSERT에서 card_id 누락
**파일:** `backend/app/services/go100/live_trading/live_engine.py:711-733`

```python
# Before (누락)
INSERT INTO go100_live_orders
(user_id, account_id, stock_code, stock_name, order_type, quantity,
 target_price, order_price, status, kis_order_id, side,
 safety_check_passed, created_at)
SELECT :uid, :aid, :code, ...

# After (수정)
INSERT INTO go100_live_orders
(user_id, account_id, card_id, stock_code, stock_name, order_type, quantity,
 target_price, order_price, status, kis_order_id, side,
 safety_check_passed, created_at)
SELECT :uid, :aid, :cid, :code, ...
```

**영향:** go100_live_orders에 기록되는 실시간 주문 로그에 card_id가 NULL로 저장됨

#### 1-2. go100_orders에 실매매 주문 미기록
**파일:** `backend/app/services/go100/live_trading/live_engine.py`

**현황:**
- ✓ paper_engine: go100_orders에 INSERT (line 513, card_id 포함)
- ✓ risk_engine: go100_orders에 INSERT (line 466, card_id 포함)
- ✗ live_engine: go100_orders에 INSERT하지 않음 → go100_live_orders만 사용

**영향:** 실매매 주문이 go100_orders 테이블에 기록되지 않아 order_id 없음

## 3. 백필 SQL

기존 go100_orders의 NULL 데이터를 포트폴리오 기준으로 매핑 복구:

```sql
-- DRY-RUN: NULL 주문 확인
SELECT COUNT(*) as null_count
FROM go100_orders
WHERE go100_card_id IS NULL;

-- 백필: go100_portfolios 기준 매핑
BEGIN;
UPDATE go100_orders o
SET go100_card_id = pf.go100_card_id
FROM go100_portfolios pf
WHERE o.portfolio_id = pf.portfolio_id
  AND o.go100_card_id IS NULL
  AND pf.go100_card_id IS NOT NULL;

SELECT COUNT(*) as updated_count;
COMMIT;

-- 검증: 남은 NULL 확인
SELECT COUNT(*) as remaining_null
FROM go100_orders
WHERE go100_card_id IS NULL;
```

**매핑 로직:**
1. go100_orders.portfolio_id → go100_portfolios 조인
2. go100_portfolios.go100_card_id 추출 (portfolio당 정확히 1개의 카드)
3. NULL 값에만 UPDATE 적용

**안전성:**
- 포트폴리오 기준 1:1 매핑이므로 오류 위험 없음
- 데이터 트랜잭션으로 원자성 보장
- DRY-RUN SELECT로 먼저 확인 가능
