# 모의계좌 발급 난이도·포털 ID/비밀번호 저장 관리 연구 보고서

**작성일**: 2026-02-24  
**목적**: (1) 모의계좌 발급이 어렵다는 사용자 피드백 반영 방안, (2) 한투 등 증권사 개발자 포털 **별도 ID/비밀번호**를 우리 서비스에서 저장·관리할 수 있는지 연구 및 정리

---

## 1. 모의계좌 발급이 어려운 문제

### 1.1 원인 정리

- **API 발급 전 선행 조건**: 한국투자증권 등은 오픈API(앱키·시크릿) 발급 전에 **모의투자 신청**이 완료되어 있어야 하는 경우가 많음.
- **진입 경로가 분산**: “모의투자 신청”은 **한투 MTS 앱** 또는 **한국투자증권 홈페이지**에서 하고, “앱키 발급”은 **개발자 포털(apiportal.koreainvestment.com)** 에서 하므로, 사용자가 **순서와 위치**를 한 번에 파악하기 어렵음.
- **용어·메뉴**: “모의투자”, “모의 계좌”, “API 신청”, “앱 등록” 등이 서로 다른 화면에 있어 혼동 가능.

### 1.2 이미 반영한 개선 (API 튜토리얼)

- **API 발급 절차 안내**를 **모달형 튜토리얼**로 도입함.
- **모의 계좌** 선택 시 튜토리얼 1단계에서 다음을 명시:
  - “모의 계좌를 쓰시려면 **한국투자증권 한투(MTS) 앱** 또는 홈페이지에서 **모의투자 신청**을 먼저 완료해 주세요.”
  - “한투 앱을 이미 쓰고 계시면 **같은 계정**으로 개발자센터에 로그인하시면 됩니다.”
- 사용자가 **순서(모의투자 신청 → 개발자센터 접속 → 앱 등록 → 키 복사)** 를 한 흐름으로 따라 할 수 있도록 구성.

### 1.3 추가로 검토할 수 있는 방안

| 방안 | 설명 | 비고 |
|------|------|------|
| **모의투자 신청 링크** | 튜토리얼 1단계에 “모의투자 신청하기” **공식 페이지 링크** 추가 (한국투자증권 홈페이지 또는 MTS 앱 스토어 링크). | 링크 유효성 주기적 점검 필요. |
| **단계 수 분리** | “0단계: 모의투자 신청”을 별도 슬라이드로 두어, 모의 선택 시에만 노출. | 현재는 1단계 본문에 포함. 필요 시 슬라이드 분리 가능. |
| **FAQ/도움말** | “모의계좌만 쓰고 싶을 때” 전용 FAQ에 “1) MTS에서 모의투자 신청 2) 개발자센터에서 앱 등록(모의 전용) 3) GO100에 키 입력” 정리. | 문서화로 재방문 시 참고 가능. |

## 2. 포털 ID/비밀번호 “우리 쪽에 저장·관리” 가능 여부

### 2.1 질문의 범위

- **저장 대상**: 한국투자증권 **개발자 포털(apiportal.koreainvestment.com)** 로그인에 쓰는 **ID·비밀번호**.
- **목적**: 사용자가 매번 잊어버리지 않도록 우리 서비스에서 “저장·관리”해 줄 수 있는지.

참고: **앱키(App Key)·앱 시크릿(App Secret)** 은 이미 우리 서비스에 암호화 저장되어 있으며, 실거래/모의 API 호출에는 이 키만 사용합니다. “별도 ID/비번”은 **포털 로그인용**을 말하는 것으로 이해했습니다.

### 2.2 결론 요약

| 구분 | 권장 |
|------|------|
| **포털 로그인 ID·비밀번호 저장** | **저장하지 않는 것을 권장**함. (보안·약관·규제 리스크) |
| **대안** | 비밀번호 관리자 안내, 포털 “비밀번호 찾기” 링크 제공, 필요 시 “포털 로그인 정보는 저장하지 않습니다” 안내 문구. |

### 2.3 저장을 권장하지 않는 이유

#### (1) 보안·리스크

- 우리 DB에 **포털 로그인 정보**가 들어가면, **유출 시 증권사 포털까지 로그인**될 수 있음.
- 증권사 포털에서 앱 추가·키 재발급·권한 변경 등이 가능하므로, 피해 범위가 큼.
- **앱키·시크릿**만 저장하는 현재 방식이 노출 시에도 “키 재발급”으로 차단 가능한 수준인 반면, **ID/비번** 유출은 계정 전체 접근으로 이어짐.

#### (2) 이용약관·금융 관행

- 금융·증권 사이트는 일반적으로 **로그인 자격증명을 제3자에게 제공·저장하지 말 것**을 요구하거나, “본인만 사용” 원칙을 둠.
- 우리가 “포털 ID/비번 저장”을 하면 **제3자 보관**에 해당할 가능성이 크며, 증권사 이용약관과 충돌할 수 있음.
- 정확한 해석은 각 증권사 이용약관 및 고객센터 확인이 필요하나, **저장하지 않는 쪽이 안전**함.

#### (3) 규제·정보보호

- 금융위·금융보안원 등은 오픈API 이용기관에 **API 접근키 보호**, **정보자산 보호**, **부정접근 방지** 등을 요구함.
- 포털 로그인 정보까지 우리가 보관하면 **관리 대상 자산·리스크**가 늘어나고, 유출 시 책임 논의가 복잡해짐.

#### (4) 실제 필요성

- **API 호출**에는 **앱키·앱 시크릿**만 필요하고, 이는 이미 우리 쪽에 암호화 저장·관리 중임.
- 포털 ID/비번이 필요한 순간은 **키 재발급·앱 설정 변경·비밀번호 변경** 등 **가끔 포털에 들어갈 때**뿐임.
- “매번 잊어버린다”는 불편은 **비밀번호 관리자 사용** 또는 **포털 비밀번호 찾기**로 해소하는 편이, 우리가 자격증명을 보관하는 것보다 리스크가 작음.

### 2.4 우리 서비스에서 할 수 있는 대안

| 대안 | 내용 |
|------|------|
| **비밀번호 관리자 안내** | 계좌 등록 또는 설정 화면에 “개발자 포털 로그인 정보는 **비밀번호 관리자**(스마트폰·PC 내장 또는 1Password 등)에 저장해 두시면 편합니다” 안내 문구 또는 도움말 링크. |
| **비밀번호 찾기 링크** | “개발자 포털 로그인을 잊으셨나요?” 문구 + **한국투자증권 개발자 포털 비밀번호 재설정** 링크 제공. (예: apiportal.koreainvestment.com 내 비밀번호 찾기/재설정 URL) |
| **저장하지 않는다는 명시** | “포털 로그인(ID/비밀번호)은 보안상 **저장하지 않습니다**. 앱키·시크릿만 암호화 저장됩니다.” 문구로 사용자 기대치 조정. |
| **키 재발급 안내** | “키를 잊으셨다면 개발자 포털에 로그인해 동일 앱에서 키를 다시 확인할 수 있습니다” + 포털 링크. (우리는 앱키·시크릿만 저장하므로 “키 분실” 시 포털에서 확인 후 우리 계좌 설정에서 키만 재입력하면 됨.) |

### 2.5 “저장”을 반드시 고려해야 할 경우 (참고)

만약 사업상 **포털 ID/비번 저장**이 필수로 검토된다면:

- 증권사 **이용약관·개발자 가이드**에 “제3자 보관” 허용 여부 **문의·확인**.
- 저장 시 **암호화(예: AES-256)** 및 **접근 권한 최소화**, **감사 로그** 등 **금융권 수준 보안 요구사항** 적용.
- **사용자 동의** 및 “포털 로그인 정보를 암호화해 보관합니다. 증권사 약관을 확인하세요” 등 **명시적 안내**.

다만 위와 같이 해도 **약관 위반·규제 리스크** 가능성이 남으므로, **현 단계에서는 저장하지 않고 대안만 제공**하는 것을 권장합니다.

---

## 3. 정리

- **모의계좌 발급**: API 발급 튜토리얼에 “모의투자 신청 선행”을 1단계에 반영해 두었음. 필요 시 모의투자 신청 링크·FAQ 보강.
- **포털 ID/비밀번호 저장**: **저장하지 않는 것**을 권장. 대신 비밀번호 관리자 안내, 포털 비밀번호 찾기 링크, “우리는 앱키·시크릿만 저장한다”는 안내, 키 재발급 방법 안내로 사용자 불편을 줄이는 방향이 적절함.

이 방향으로 정책을 정한 뒤, 필요한 UI 문구·링크만 추가하면 됩니다.
