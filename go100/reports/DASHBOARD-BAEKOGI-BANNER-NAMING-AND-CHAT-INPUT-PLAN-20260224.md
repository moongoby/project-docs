## 2. 요청 1: 대시보드 상단에 “백억이” 이름 넣기

### 2.1 현황

- 인사 문구는 **“좋은 아침이에요! ☀️ 투자자님”** 형태로만 노출됨.
- “백억이와 대화하기” 버튼과 면책 문구에서만 “백억이”가 등장하고, **인사 블록 자체에는 “백억이”가 없음.**

### 2.2 기획 방향

- **인사 한 줄에 “백억이”를 명시**해, 이 영역이 백억이(AI) 인사·요약 구역임을 바로 알 수 있게 함.

### 2.3 제안 문구 (택 1 또는 유사 적용)

| 옵션 | 표기 예시 | 비고 |
|------|-----------|------|
| A | **백억이** · 좋은 아침이에요! ☀️ 투자자님 | 짧고 구분자로 역할 명확 |
| B | 백억이가 인사해요 — 좋은 아침이에요! ☀️ 투자자님 | 문장형, 다소 김 |
| C | 🤖 **백억이**: 좋은 아침이에요! ☀️ 투자자님 | 접었을 때와 톤 통일(현재 접힌 상태는 "🤖 백억이: ...") |

**권장**: **옵션 A** 또는 **옵션 C**.  
- 펼친 상태: `백억이 · 좋은 아침이에요! ☀️ {displayName}` 또는 `🤖 백억이: 좋은 아침이에요! ☀️ {displayName}`
- 접힌 상태는 이미 `🤖 백억이: {greetingText} {emoji} {displayName}` 이므로, 펼친 상태만 옵션 A/C로 맞추면 됨.

### 2.4 반영 포인트

- **파일**: `BaekogiWelcomeBanner.tsx`
- **수정 위치**: 펼친 상태에서 인사 문구가 나오는 `<p className="font-semibold text-white">` 블록.
- **변경 예**:  
  `{greetingText} {emoji} {displayName}`  
  → `백억이 · ${greetingText} ${emoji} ${displayName}` 또는 `백억이: ${greetingText} ${emoji} ${displayName}`

## 3. 요청 2: 백억이 박스(배너)에 채팅 입력창 넣기

### 3.1 현황

- “백억이와 대화하기”는 **링크 버튼** → 클릭 시 `/llm`(전체화면 채팅)으로 이동.
- 우측 하단 FAB으로 **채팅 위젯**(`ChatWidget`)이 있으며, 열면 입력창 + 대화 패널이 있음.
- 배너 안에는 **즉시 입력 가능한 채팅 입력창이 없음.**

### 3.2 기획 방향

- 배너 안에 **채팅 입력창(텍스트 + 전송)**을 두어, 대시보드에 머무른 채로 바로 질문을 입력·전송할 수 있게 함.

### 3.3 UX 옵션

| 방식 | 설명 | 장점 | 단점 |
|------|------|------|------|
| **A. 배너 인라인 입력 + 전송 시 위젯 열기** | 배너에 입력창·전송 버튼 추가. 전송 시 우측 하단 채팅 위젯을 자동으로 열고, 해당 메시지를 넣어 전송(및 AI 응답 표시). | 대시보드 이탈 없음, 기존 위젯과 대화 연속성 유지 | 위젯 열림 + 메시지 주입 연동 필요(이벤트/컨텍스트 등) |
| **B. 배너 인라인 입력 + 전송 시 /llm 이동** | 전송 시 `/llm`으로 이동하면서 **쿼리 파라미**(예: `?message=...` 또는 `?q=...`)로 입력 내용 전달. /llm 페이지 마운트 시 해당 값을 채팅 입력창에 넣고 자동 전송 또는 placeholder로 표시. | 구현 단순, 전체화면 채팅과만 연동 | 대시보드에서 다른 화면으로 이동함 |
| **C. 배너는 “한 줄 입력 + 전송”만, 전송 시 위젯에 메시지 전달** | A와 동일하되, “배너에서 보낸 메시지”를 전역 이벤트 또는 React Context로 전달하고, ChatWidget이 열릴 때(또는 이미 열려 있으면) 그 메시지를 추가 후 API 호출. | 한 곳(위젯)에서만 대화 관리, 배너는 진입점만 제공 | 위젯·배너 간 통신 설계 필요 |

### 3.4 권장: 옵션 A/C (배너 입력 → 위젯에서 대화)

- 대시보드를 **그대로 두고** 대화만 하고 싶은 사용자에게 적합.
- 기존 채팅 위젯이 이미 `chatWithAI` 호출·메시지 목록·로딩 상태를 갖고 있으므로, “배너에서 보낸 첫 메시지”만 위젯에 넘기면 됨.

**동작 시나리오**

1. 사용자가 배너 입력창에 문구 입력 후 전송.
2. (선택) 배너 입력창은 비우거나 “전송됨” 등 짧은 피드백.
3. 우측 하단 **채팅 위젯이 열림** (이미 열려 있으면 유지).
4. 위젯 쪽에서 해당 메시지를 user 메시지로 추가하고 `chatWithAI` 호출 → 응답을 assistant 메시지로 추가.

**기술 포인트**

- **배너 → 위젯 메시지 전달**:  
  - 방법 1: `window.dispatchEvent(new CustomEvent('go100-send-message', { detail: { text } }))` 등 커스텀 이벤트.  
  - 방법 2: React Context(예: `BaekogiChatContext`)에서 “pendingMessage” 같은 값을 두고, 배너는 set, 위젯은 구독 후 소비.
- **위젯 열기**: ChatWidget이 전역에 1개 있으므로, 동일 이벤트/컨텍스트에서 “열림 상태 + 메시지”를 함께 제어.  
  예: 이벤트 리스너에서 `setOpen(true)` 후 메시지 큐에 넣고, 위젯이 열릴 때 큐를 비우며 `sendMessage`에 넘김.
- **배너 UI**:  
  - 기존 4개 버튼 영역 중 “백억이와 대화하기”를 **입력창 + 전송 버튼**으로 대체하거나,  
  - 버튼 행 위/아래에 한 줄 **인라인 입력 + 전송** 추가 (레이아웃에 따라 1줄 또는 2줄).

### 3.5 대안: 옵션 B (전송 시 /llm 이동)

- “전체화면 채팅에서 이어서 대화”를 우선하면, 전송 시 `router.push(\`/llm?q=${encodeURIComponent(text)}\`)` 하고, `/llm` 페이지에서 `searchParams.q`를 읽어 입력창에 넣은 뒤 자동 전송(또는 placeholder) 처리하면 됨.
- 구현이 단순하지만, 사용자는 대시보드를 떠나게 됨.

## 4. 요약 및 제안 순서

| 항목 | 내용 | 우선순위 |
|------|------|----------|
| **1. 백억이 이름** | 배너 인사 문구에 “백억이” 표기 (예: `백억이 · 좋은 아침이에요! ☀️ 투자자님`) | 1단계: UI 텍스트만 수정 |
| **2. 채팅 입력창** | 배너에 입력창 + 전송 버튼 추가. 전송 시 채팅 위젯 열고 해당 메시지 전달·전송(옵션 A/C). 또는 전송 시 /llm 이동 + 쿼리로 문구 전달(옵션 B). | 2단계: 이벤트/컨텍스트 또는 라우팅 연동 |
