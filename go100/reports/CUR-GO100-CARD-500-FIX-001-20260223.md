## 2. 원인 분석 (traceback)

### 2-1. 로그에서 확인한 에러

- **에러 클래스**: `asyncpg.exceptions.PostgresSyntaxError: syntax error at or near ":"`
- **발생 위치**: `card_service.py` line 186 — `db.execute(text(""" INSERT INTO go100_strategy_cards ... """))`
- **실제 전달된 SQL 조각** (journalctl 로그):
  ```text
  INSERT INTO go100_strategy_cards ( ... ) VALUES (
      $1, $2, $3, :universe_filter::jsonb,
      :entry_rules::jsonb, :exit_rules::jsonb, :risk_params::jsonb, :strategy_params::jsonb,
      $4, $5, $6, $7, $7
  )
  ```
- **원인**: asyncpg는 **위치 파라미터($1, $2, …)** 만 인식함. SQLAlchemy PostgreSQL 다이얼렛이 `CAST(:param AS jsonb)` 를 `:param::jsonb` 형태로 렌더링하면서, 일부 바인딩만 `$n`으로 치환되고 **`:universe_filter` 등이 그대로 남아** PostgreSQL이 `:` 근처에서 구문 오류를 냄.

## 3. 수정 내용

### 3-1. 변경 파일

- `backend/app/services/go100/strategy/card_service.py` (create_card INSERT)

### 3-2. 변경 요지

- **기존**: `CAST(:universe_filter AS jsonb)`, `CAST(:entry_rules AS jsonb)` 등
- **변경**: `(SELECT :universe_filter)::jsonb`, `(SELECT :entry_rules)::jsonb` 등
- **이유**: 바인딩 토큰(`:param`)을 `::` 와 분리하여, named → positional 치환이 안정적으로 이루어지도록 함. 실행 시 `(SELECT $n)::jsonb` 형태가 되어 구문 오류가 사라짐.

### 3-3. 백업

- `card_service.py.bak` 생성 후 수정 적용.
