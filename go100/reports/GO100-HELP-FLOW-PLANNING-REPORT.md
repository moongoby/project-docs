# 백억이 화면·사용법 도움 기능 기획 보고서

**문서 번호:** GO100-HELP-FLOW  
**작성일:** 2026-02-24  
**목적:** 백억이가 “전략 설계” 외에 “시스템 화면 설명·사용법 도움”을 제공할 수 있도록 하는 기획 및 기술 방안 정리

---

## 1. 배경 및 목표

### 1.1 배경

- 현재 백억이 채팅은 **투자 의도 추출(UNDERSTAND) → 전략 설계(DESIGN)** 전용으로만 동작한다.
- “대시보드 이 버튼이 뭐예요?”, “전략 카드는 어디서 저장해요?” 같은 **화면/사용법 질문**에 대해 적절한 답변을 주지 못한다.
- 사용자는 같은 채팅 창에서 **전략 요청**과 **사용법 질문**을 모두 하고 싶어 할 수 있다.

### 1.2 목표

| 구분 | 내용 |
|------|------|
| **기능 목표** | 백억이가 GO100/시스템 화면 설명·메뉴 위치·사용법·자주 묻는 질문에 대해 안내할 수 있게 한다. |
| **체험 목표** | 사용자가 “전략 만들어줘”와 “이 화면 어떻게 써?”를 한 대화 흐름에서 자연스럽게 묻고, 각각에 맞는 답을 받는다. |
| **제약** | 기존 전략 설계 파이프라인(UNDERSTAND→DESIGN→백테스트 등)은 유지하고, 사용법 전용 경로만 추가한다. |

### 1.3 범위

- **포함:** 채팅 진입점 동일, 백엔드에서 “전략 vs 사용법” 구분 후 사용법일 때만 별도 흐름 + 지식(문서/FAQ) 기반 답변.
- **미포함(1차):** 실시간 시세/DB를 LLM에 넣는 기능, 음성/멀티미디어 입력, 타 서비스(예: KIS API) 상세 기술 지원.

## 2. 현황 분석

### 2.1 현재 채팅 흐름

```
[사용자 메시지] → POST /api/go100/ai/chat
  → UNDERSTAND (투자 의도만 추출)
  → needs_clarification ? clarify 반환 : DESIGN
  → DESIGN → (DB 있으면) 백테스트 파이프라인
  → call_reply (intent/design 기반 설명)
```

- **한계:** 모든 메시지가 “투자 의도”로만 해석되며, 화면/사용법 질문은 의도 파악 실패 또는 부적절한 전략 응답으로 이어진다.
- **지식 한계:** LLM에 화면 구조·메뉴·사용법 문서가 전달되지 않는다.

### 2.2 참조 문서(기존)

| 문서 | 용도 |
|------|------|
| `docs/go100-architecture-v1.1.md` | GO100 아키텍처·화면/플로우 개요 |
| `docs/API_SPEC.md`, `docs/DB_SCHEMA.md` | API·DB (운영/개발용, 사용자 안내에는 요약만 활용 가능) |
| `docs/HANDOVER.md`, `docs/PLANNING.md` | 프로젝트 맥락 |
| `report/GO100-PROCESS-FLOW-REPORT.md` | 백억이 프로세스·LLM 사용 정리 |

- **사용자용 안내 문서:** 현재 **화면별 사용법·FAQ**가 한곳에 정리된 문서는 없음. 신규 작성 필요.

## 3. 기획 요약

### 3.1 핵심 설계

1. **의도 분기(라우팅)**  
   사용자 메시지를 **“전략 설계”** vs **“화면/사용법(도움)”** 으로 구분한다.
2. **사용법 전용 흐름**  
   “도움”으로 분기된 경우 기존 UNDERSTAND/DESIGN을 타지 않고, **도움 전용 처리기**만 수행한다.
3. **지식 주입**  
   화면 설명·메뉴·FAQ를 **문서/구조화 데이터**로 관리하고, 도움 흐름에서만 LLM에 context로 넣어 답변을 생성한다.

### 3.2 사용자 시나리오

| 시나리오 | 사용자 발화 예 | 기대 동작 |
|----------|----------------|-----------|
| 전략 요청 | “5일선 골든크로스에 사고 5일선 깨면 팔아줘” | 기존대로 UNDERSTAND → DESIGN → (백테스트) → 전략 설명 |
| 사용법 질문 | “대시보드에서 전략 카드 저장은 어디서 해요?” | 도움 흐름 → 화면/메뉴 지식 기반으로 “어디서 어떻게 하는지” 안내 |
| 혼합 | “방금 만든 전략 저장했는데, 백테스트는 어디서 돌려요?” | 1) 전략 관련은 이미 완료된 맥락, 2) “백테스트 실행 위치”는 도움 지식으로 답변 |

### 3.3 적용 범위 옵션: 채팅 위젯에서만 도움 제공 (별도 진행 가능)

**질문:** 화면/사용법 도움을 **채팅 위젯에서만** 켜고, 전체화면 채팅(/llm)은 전략 전용으로 둘 수 있는가?

**답:** 가능하다. 별도 진행해도 된다.

| 구분 | 내용 |
|------|------|
| **의도** | 위젯 = "어디서든 빠르게 물어보기" → 전략 + 사용법 모두 허용. /llm = "전략 만들기에 집중" → 전략만 허용. |
| **구현** | 프론트에서 **발신처 구분**을 body에 넣고, 백엔드에서는 **그 값이 있을 때만** 라우터·HelpFlow를 타도록 분기. |
| **프론트** | `ChatWidget`에서만 `chatWithAI({ ..., source: "widget" })` 또는 `enable_help: true` 전달. `ChatInterface`(전체화면)에서는 해당 필드 생략 또는 `source: "fullscreen"`. |
| **백엔드** | `source === "widget"`(또는 `enable_help === true`)일 때만 Intent Router 실행 → help 분기 시 HelpFlow 수행. 그 외에는 **현재와 동일**하게 UNDERSTAND → DESIGN만 수행(도움 흐름 비활성). |
| **효과** | 전체화면 채팅은 기존 동작 유지, 위젯만 도움 기능 추가. 롤아웃 범위를 위젯으로 제한해 검증 후 /llm까지 확장 가능. |

이렇게 하면 **채팅 위젯에서만 화면/사용법 도움**을 주는 형태로 별도 진행할 수 있다.

## 4. 기술 방안

### 4.1 아키텍처 개요

```
[사용자 메시지]
       │
       ▼
┌──────────────────┐
│  Intent Router   │  ← 신규: "strategy" | "help" | "unknown"(→ strategy 유지)
└────────┬─────────┘
         │
    ┌────┴────┐
    ▼         ▼
 strategy   help
    │         │
    ▼         ▼
[기존 파이프라인]  [HelpFlow]  ← 신규
 UNDERSTAND        │
 DESIGN            ├─ 지식 로드 (화면/FAQ)
 백테스트 등        ├─ LLM: context = 지식 + 대화 + 질문
    │              └─ reply_to_user 반환
    ▼
 reply_to_user
```

- **진입점:** 기존 `POST /api/go100/ai/chat` 유지. 라우터를 오케스트레이터 **앞단**에 두어, `process_message` 호출 전에 분기하거나, `process_message` 내부 첫 단계에서 분기하도록 구현 가능.

### 4.2 의도 분기(라우터) 상세

| 항목 | 내용 |
|------|------|
| **위치** | `backend/app/services/go100/ai/` 하위 신규 모듈 (예: `intent_router.py` 또는 `base_orchestrator.py` 내 첫 단계). |
| **입력** | `user_message`, (선택) `conversation_history` 최근 N턴. |
| **출력** | `intent_type: "strategy" | "help"` (및 필요 시 `confidence`). |
| **구현 옵션** | (A) 경량 규칙: 키워드/패턴(예: “어디서”, “뭐야”, “사용법”, “도움”, “버튼”, “메뉴”) + 길이 등으로 1차 분류. (B) 소형 LLM 호출: FREE_CHAT 1회로 “이 문장은 투자 전략 요청인가, 앱 사용법/화면 질문인가?”만 판별. (C) A+B: 규칙으로 명확한 것 먼저 처리, 애매하면 B. |
| **unknown 처리** | 라우터가 “help”로 확신하지 못하면 기존처럼 `strategy`로 두어 기존 파이프라인 유지. (기존 동작 깨지지 않도록 보수적으로) |

### 4.3 사용법 전용 흐름(HelpFlow)

| 항목 | 내용 |
|------|------|
| **역할** | “help”로 분기된 메시지에 대해, **화면/사용법 지식**을 넣고 LLM으로 친근한 안내 문장만 생성. |
| **입력** | `user_message`, `conversation_history`(선택), (선택) `current_screen` 등 클라이언트 메타. |
| **지식 소스** | 아래 5절의 **화면·사용법 문서 + FAQ**를 텍스트/JSON으로 로드. |
| **프롬프트** | system: “당신은 GO100 사용법 안내 어시스턴트다. 제공된 [화면 설명·FAQ]만 사용해 답변하고, 없으면 ‘해당 내용은 아직 안내 문서에 없어요’ 등으로 정중히 말한다.” user: “[지식 요약/관련 조각] + 사용자 질문 + (선택) 최근 대화”. |
| **출력** | `reply_to_user` 문자열. 응답 스키마는 기존 `OrchestrationResult`와 호환(예: `agent_name="HELP"`, `status="completed"`). |
| **LLM** | 기존 FREE_CHAT(Gemini) 재사용으로 비용·일관성 유지. |

### 4.4 기존 채팅과의 통합

- **API:** `POST /api/go100/ai/chat` 그대로. body에 선택 필드 `source?: "widget" | "fullscreen"` 또는 `enable_help?: boolean` 추가 가능. 위젯에서만 도움 켜기 시 `source === "widget"`일 때만 라우터·HelpFlow 수행.
- **응답:** 기존 `OrchestrationResult` 유지. `agent_name`으로 "ORCHESTRATOR" | "UNDERSTAND" | "HELP" 등 구분 가능하게 하면 프론트에서 로그/UI 분기 가능.
- **프론트:** 채팅 위젯에서만 도움 제공 시 ChatWidget에서만 `source: "widget"` 전달, ChatInterface(전체화면)는 생략. 두 클라이언트 모두 `reply_to_user`만 표시하면 되므로 수정 최소화. (필요 시 “전략이 생성되었어요” vs “사용법 안내예요” 등 뱃지 추가 가능)

## 5. 화면·사용법 지식(문서·FAQ) 구성

### 5.1 지식 구조 제안

| 구분 | 설명 | 형식 예 | 비고 |
|------|------|----------|------|
| **화면 설명** | 화면별 목적, 주요 버튼/메뉴, 한두 줄 설명 | Markdown 또는 JSON (화면 ID, 제목, 설명, 주요 액션) | GO100 대시, 전략 목록, 전략 상세, 백테스트, 모의거래, 실거래, 설정 등 |
| **메뉴/경로** | “전략 저장은 어디서?” → 경로(URL/메뉴 이름) | FAQ 스타일 Q&A 또는 구조화 Q→A | 사이드바·상단 메뉴 기준 |
| **FAQ** | 자주 묻는 질문과 짧은 답변 | Q&A 리스트 (질문, 답변, 키워드/태그) | 비밀번호, 계좌 연결, 전략 카드 저장, 백테스트 실행, 모의/실거래 시작 등 |
| **용어/개념** | GO100, 전략 카드, 백테스트, 모의거래 등 한 줄 정의 | 짧은 문장 또는 표 | LLM이 지식에 없을 때 “용어는 있지만 상세는 문서에 없음”으로 빠르게 응답 가능 |

### 5.2 문서 위치 및 형식 제안

| 항목 | 경로 제안 | 형식 |
|------|-----------|------|
| 화면 설명 | `docs/go100/user-guide/screens.md` (또는 `screens.json`) | 화면 ID, 이름, 설명, 주요 메뉴/버튼 |
| FAQ | `docs/go100/user-guide/faq.md` (또는 `faq.json`) | 질문, 답변, 키워드 |
| 메뉴/경로 | `docs/go100/user-guide/navigation.md` 또는 FAQ에 통합 | “~하려면” → 경로/메뉴 |
| 통합 지식 (LLM 주입용) | 빌드/런타임에 위를 합친 단일 텍스트 또는 JSON | `HelpFlow`에서 로드해 system/user context에 포함 |

### 5.3 지식 예시(초안)

**화면 설명 예:**

```markdown
## GO100 대시보드 (/go100)
- 최근 전략 카드 요약, 빠른 액션(새 전략 만들기, AI 대화)
- "AI 대화 바로가기" → 전체화면 채팅(/llm)
- "새 전략 만들기" → /go100/chat 또는 /llm

## 내 전략 (/go100/strategies)
- 보유 전략 카드 목록, 검색, 전체/내 전략 탭
- 카드 클릭 → 상세(/go100/strategies/[id])
- 전략 저장(채팅에서 설계 후) → "전략 저장" 버튼 또는 "내 전략"에서 확인

## 백테스트 (/backtest)
- 전략 선택 후 기간 설정, 실행
- GO100 카드도 선택 가능, 결과는 전략 상세에서 확인
```

**FAQ 예:**

| 질문 | 답변 |
|------|------|
| 전략 카드 저장은 어디서 해요? | 채팅에서 전략이 나온 뒤 메시지 옆 "전략 저장" 버튼을 누르거나, 전체화면 채팅(/llm)에서 저장할 수 있어요. 저장한 카드는 "내 전략" 메뉴에서 봐요. |
| 백테스트는 어디서 돌리나요? | 상단/사이드 "백테스트" 메뉴에서 전략을 고르고 기간을 설정한 뒤 실행하면 돼요. GO100으로 만든 전략도 선택할 수 있어요. |
| 모의거래는 어떻게 시작해요? | "모의거래" 메뉴에서 시작할 수 있어요. 전략 카드를 선택하고 금액 등을 설정한 뒤 시작하면 됩니다. |

- 위와 같은 식으로 `docs/go100/user-guide/` 에 실제 화면에 맞게 채우면 된다.

## 6. 작업 항목 및 단계

### 6.1 Phase 1: 지식 정리 및 도움 흐름 골격

| 순번 | 작업 | 담당 후보 | 산출물 |
|------|------|------------|--------|
| 1.1 | `docs/go100/user-guide/` 디렉터리 및 화면 설명·FAQ 초안 작성 | 기획/개발 | `screens.md`, `faq.md` (또는 .json) |
| 1.2 | 지식 로더 유틸 (파일/디렉터리 읽어서 LLM용 텍스트 생성) | 백엔드 | `backend/app/services/go100/ai/help_knowledge.py` 등 |
| 1.3 | HelpFlow 모듈 (지식 로드 + FREE_CHAT 호출 + reply 반환) | 백엔드 | `help_flow.py` 또는 `base_orchestrator` 내 help 분기 |
| 1.4 | 라우터 모듈 (message → strategy | help) — 규칙 기반 1차 버전 | 백엔드 | `intent_router.py` 또는 `base_orchestrator` 상단 분기 |
| 1.5 | ai_router / BaseOrchestrator에서 라우터 호출 후 help 시 HelpFlow만 타고 응답 반환 | 백엔드 | 기존 `/chat` 응답 스키마 유지, `agent_name` 확장 |

### 6.2 Phase 2: 품질 및 확장

| 순번 | 작업 | 담당 후보 | 산출물 |
|------|------|------------|--------|
| 2.1 | FAQ/화면 설명 실제 메뉴·URL과 동기화 및 보강 | 기획/QA | docs 갱신 |
| 2.2 | 라우터 정확도 개선 (필요 시 소형 LLM 분류 또는 규칙 보강) | 백엔드 | intent_router v2 |

## 7. 비기능 요구사항

| 항목 | 내용 |
|------|------|
| **성능** | 도움 흐름은 UNDERSTAND+DESIGN보다 짧아야 함. 지식 크기는 1차에 4k 토큰 이내 등로 제한 검토. |
| **보안** | 지식에는 내부 API 키·비밀·개인정보 넣지 않음. 사용자 입력은 기존처럼 이스케이프/검증. |
| **규칙** | go100_* 수정 시 기존 규칙(헤더 주석, get_effective_uid 등) 유지. |
| **모니터링** | 라우터 결과(help vs strategy 비율), 도움 응답 만족도(선택) 로깅. |
