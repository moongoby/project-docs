# 키움증권 조건식 수집 기능 확인 보고서 (v2 — 기본 조건식 조사 포함)

- **일자**: 2026-02-27
- **요청**: 키움증권 조건식(조건검색) 기본 제공 조건 존재 여부 확인 및 보고

---

## 1. 핵심 결론: 기본 제공 조건식은 API에서 사용 불가

### 1-1. 키움증권 HTS 기본 조건식 — 있으나 API 미지원

키움증권 영웅문4 HTS에는 기본 제공 조건식이 존재합니다:

| 서비스 | 내용 | API 사용 |
|--------|------|----------|
| **조건검색 [0150]** | '저평가된 성장주', '꾸준히 배당을 주는 종목', '돈 잘 버는 회사' 등 | **불가** |
| **캐치(KATCH) [4000]** | 82개 초단위 조건검색식 (키움 자체 선정) | **불가** |

**이 기본 조건식들은 HTS 화면 전용이며, API(ka10171 목록조회)에서는 나타나지 않습니다.**

### 1-2. API에서 사용 가능한 조건식 — 사용자 직접 생성 필수

```
기본 조건식 (HTS 내장)     → HTS/캐치 서비스 전용, API 사용 불가 ✗
사용자 조건식 (직접 생성)   → HTS에서 생성 → "서버 저장" → API로 목록 조회·실행 가능 ✓
API에서 조건식 생성/편집    → 불가 ✗
```

**Windows PC에서 영웅문4 HTS를 실행하여 조건식을 직접 만들고 "사용자조건 서버저장"을 클릭하는 것이 필수 전제조건**입니다.

## 2. 증권사별 조건검색 API 비교

### 2-1. 키움증권 REST API (현재 코드에서 사용 중)

| API ID | 이름 | 프로토콜 | 용도 |
|--------|------|----------|------|
| ka10171 | 조건검색 목록조회 | **WebSocket** | 서버 저장 조건식 목록 조회 |
| ka10172 | 조건검색 요청 일반 | **WebSocket** | 1회성 조건검색 실행 |
| ka10173 | 조건검색 요청 실시간 | **WebSocket** | 실시간 조건검색 등록 |
| ka10174 | 조건검색 실시간 해제 | **WebSocket** | 실시간 등록 해제 |

- 접속: `wss://api.kiwoom.com:10000/api/dostk/websocket`
- **WebSocket 전용** — 일반 HTTP REST가 아님
- 제한: 1초 5회, 조건별 1분 1회, 실시간 최대 10개, 100종목 초과 시 실시간 불가
- 현재 코드의 ka10050은 REST 방식이지만, 키움 공식 조건검색은 WebSocket 기반

### 2-2. KIS(한국투자증권) REST API — 대안으로 활용 가능

| API ID | TR_ID | URL | 프로토콜 | 용도 |
|--------|-------|-----|----------|------|
| 국내주식-038 | HHKST03900300 | `/uapi/.../psearch-title` | **HTTP REST** | 조건 목록 조회 |
| 국내주식-039 | HHKST03900400 | `/uapi/.../psearch-result` | **HTTP REST** | 조건 결과 조회 |

- **이미 kis_api_registry.py에 등록됨** (`condition_search_list`, `condition_search_result`)
- HTTP REST 방식 → WebSocket 불필요, 구현 간편
- 파라미터: `user_id` (HTS ID 필수), `seq` (조건 키값)
- 응답: 종목코드, 종목명, 현재가, 등락률, 거래량, 체결강도, 시가총액 등 풍부
- **단, eFriend Plus HTS에서 조건식을 만들고 "사용자조건 서버저장"을 해야 사용 가능 (키움과 동일)**
- **모의투자 미지원** — 실전계좌만 가능

## 3. 현재 시스템 구현 현황

### 3-1. 구현된 항목

| 구성요소 | 파일 | 상태 |
|----------|------|------|
| 수집기 (키움) | `condition_search_collector.py` → ka10050 | 구현 완료 |
| DB 테이블 | `v4_condition_search` (11컬럼) | 생성 완료 |
| Phase3 스케줄러 | 09:00~15:30 매 5분 | 등록 완료 |
| API 엔드포인트 | `GET /api/v1/market/condition-search` | 등록 완료 |
| KIS API 등록 | `kis_api_registry.py` (psearch-title/result) | 등록만 됨 (미사용) |

### 3-2. 운영 상태: 미작동

```
Phase3 condition_search: {'ok': 0, 'inserted': 0, 'conditions': 0, 'skipped': 'no_condition_list'}
```

원인: 조건식 목록 미등록 (HTS에서 조건식 생성 필요)

## 4. 활성화 방안 (3가지 옵션)

### 옵션 A: 키움 HTS에서 조건식 생성 (현재 코드 활용)

1. Windows PC에서 키움 영웅문4 로그인 (account_id=4 계정)
2. [0150] 조건검색 화면에서 조건식 생성 (예: 급등주, 거래량폭증 등)
3. 왼쪽 하단 "사용자조건 서버저장" 클릭
4. `config/condition_search.json`에 조건명/ID 등록
5. 서비스 재시작 → 5분마다 자동 수집 시작

**난이도**: 중 (Windows PC + HTS 필요)

### 옵션 B: KIS(한투) API psearch로 전환 (권장)

1. eFriend Plus HTS에서 조건식 생성 + 서버저장
2. 수집기를 KIS API(`psearch-title` → `psearch-result`) 방식으로 전환
3. HTTP REST 방식이라 WebSocket 불필요, 구현 간편
4. KIS 계좌가 이미 있으므로 인증 인프라 재활용 가능

**난이도**: 중 (HTS 필요 + 수집기 코드 수정)

### 옵션 C: 조건식 대체 — 자체 스크리닝 로직 구현 (HTS 불필요)

증권사 조건식에 의존하지 않고, 이미 수집된 데이터로 자체 조건 검색:
- ohlcv_daily (일봉) → 이평선 크로스, RSI, 볼린저밴드
- v4_investor_daily (수급) → 외국인/기관 순매수
- stock_fundamentals → PER/PBR 저평가
- v4_tick_data (실시간 틱) → 거래량 급등, 체결강도

**난이도**: 상 (로직 개발 필요)
**장점**: HTS 불필요, Windows PC 불필요, 완전 자동화 가능

## 5. 종합 평가

| 항목 | 결론 |
|------|------|
| 기본 조건식 존재 여부 | HTS에는 있지만 **API에서 사용 불가** |
| API 조건검색 전제조건 | **반드시 HTS에서 사용자가 직접 조건식 생성 + 서버저장 필요** |
| 키움 vs KIS | 키움은 WebSocket, KIS는 HTTP REST (KIS가 구현 간편) |
| 현재 시스템 | 코드 구현 완료, 조건식 미등록으로 미작동 |
| 권장 방안 | **옵션 B** (KIS psearch API) 또는 **옵션 C** (자체 스크리닝) |

**결론**: 키움증권이든 한국투자증권이든, 조건검색 API를 사용하려면 **Windows PC에서 HTS를 실행하여 조건식을 직접 만들고 서버에 저장하는 수동 작업**이 반드시 필요합니다. 기본 제공 조건식은 HTS 화면 전용이며 API로는 접근할 수 없습니다.

HTS 없이 운영하려면, 이미 수집된 데이터(일봉·수급·재무·틱)를 활용한 **자체 스크리닝 엔진(옵션 C)**을 구현하는 것이 가장 현실적인 대안입니다.
