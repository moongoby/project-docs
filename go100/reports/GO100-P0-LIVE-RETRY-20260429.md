### Fix 1 (P0): sync_account_snapshots.py — account_snapshots FK 위반 57일 복구

**근본 원인:**
- `account_snapshots.user_id` FK → `users.id` (legacy: 6, 15 등)
- `accounts.user_id` = `v4_users.user_id` (1, 3 등) — 완전히 다른 ID 체계
- 기존 코드: `_insert_snapshot(conn, account["user_id"], snapshot)` → FK 위반 → INSERT 실패
- 결과: 2026-03-03 이후 57일간 account_snapshots 미갱신

**수정 내용 (`scripts/cron/sync_account_snapshots.py`):**
```python
# _fetch_active_accounts에 legacy_user_id 서브쿼리 추가
(SELECT u.id FROM users u
 JOIN v4_users v ON v.email = u.email
 WHERE v.user_id = a.user_id LIMIT 1) AS legacy_user_id
```
- `legacy_user_id` None → warning 로그 + go100_error_log 기록 + skip
- `legacy_user_id` 매핑 성공 → 정상 INSERT
- Kiwoom/KIS 토큰 실패 → go100_error_log pipeline_error 기록

**검증:**
```
account_snapshots 오늘 삽입: 1건 (account_id=7, user_id=3→legacy=15)
account_snapshots 최신 snapshot_time: 2026-04-29 ✓
```

**매핑 현황:**
| account_id | v4_uid | legacy_uid | 결과 |
|-----------|--------|------------|------|
| 1 | 1 | NULL | 경고+skip (system계정 매핑 없음) |

### Fix 2: collect_minute_tier2.py — LIKE 패턴 f-string 임베드 버그 방지

**문제:** `sql = f"""... NOT LIKE 'KODEX%' ... NOT LIKE '%스팩%' ..."""` + `cur.execute(sql)` 무파라미터 호출
- psycopg2는 파라미터 없이 execute 호출 시 % 파싱 안 함 → 현재는 동작
- 하지만 향후 파라미터 추가 시 오파싱 위험 (cf. topmovers의 이전 IndexError 버그)

**수정:** `%s` 파라미터 13개로 분리, f-string 제거
```python
cur.execute("... NOT LIKE %s AND NOT LIKE %s ...",
    ('KODEX%','TIGER%','ACE%','%스팩%','%정리%','%관리%', ..., TIER2_N))
```
**검증:** 2228종목 후보 쿼리 dry-run 성공

### Fix 3: kis_condition_search_collector.py — all_skip 집계 키 추가

**문제:** 모든 계정이 `hts_id_not_set`으로 skip되어도 top-level `skipped` 키 없음
→ shell script에서 감지 불가

**수정:**
```python
all_skipped_hts = all(r.get("skipped") == "hts_id_not_set" for r in results)
skip_summary = "all_configs_hts_id_not_set" if all_skipped_hts else ""
return {"ok": ..., "skipped": skip_summary, ...}
```

**현재 상태:** 활성 kis_configs 5개, hts_id 설정 0개 → 조건검색 전체 skip
→ **해결은 코드 불가 — DB에 hts_id 입력 필요 (CEO 액션)**
