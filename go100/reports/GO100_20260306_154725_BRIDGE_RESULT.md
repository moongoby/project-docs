### 구현 내용

① 헤더
- "🔬 전략 연구소 (Research Lab)", 서브텍스트 "자율 진화 루프 현황 및 가설 관리"
- ← 종합상황실 브레드크럼 링크
- 새로고침 버튼 (animate-spin 포함)

② 진화 루프 파이프라인 시각화 (가로 스텝 플로우)
- 5단계: 가설 생성(pending) → 백테스트(testing) → 검증 완료(validated) → CEO 승인(approved) → 반려(rejected)
- 각 스텝에 현재 건수 뱃지 표시
- 각 스텝 클릭 시 해당 상태 가설 필터 적용 (isActive 토글)
- 전체 건수 별도 표시

③ 가설 목록 테이블
- go100_strategy_hypotheses 테이블 기반
- 컬럼: ID, 가설명, 전략타입(source_type), 상태, 등급(grade), 점수, 생성일, 백테스트 수익률
- 상태별 뱃지 색상: pending=amber, testing=blue, validated=purple, approved=emerald, rejected=red
- 필터: 상태 드롭다운 (전체/대기/테스트중/검증완료/승인/반려)
- 정렬: 최신순(기본), 점수순, 수익률순
- 페이지네이션 20건

④ CEO 승인 큐 (상단 강조)
- status='pending' 가설만 amber 카드로 표시
- 각 카드에 "승인" (emerald) / "반려" (red) 버튼 (isCEO = user_id=2 전용)
- 클릭 시 ApprovalModal: 확인 모달 + 사유 입력 textarea
- POST /api/go100/pending-configs/{id}/approved 또는 /rejected 호출
- 승인/반려 후 fetchData() 자동 갱신

⑤ 진화 루프 실행 로그
- 최근 10건 (go100_evolution_loop_log 우선, 없으면 go100_agent_reports fallback)
- 시각, 대상 가설 ID, action, result, elapsed_sec
- 결과 색상: success/DONE=emerald, failed/FAIL=red, 기타=gray

⑥ API 호출
- GET /api/go100/admin/research-status (limit, offset, status 파라미터)

## 작업 3: 백엔드 API

### 생성 파일
`backend/app/routers/go100/research_router.py`

### 엔드포인트

```
GET  /api/go100/admin/research-status
  - go100_strategy_hypotheses 상태별 건수 통계
  - 가설 목록 (limit, offset, status 필터)
  - EvolutionLoop 실행 로그 (go100_evolution_loop_log → fallback: go100_agent_reports)
  - graceful fallback: 테이블 없으면 빈 데이터 반환

GET  /api/go100/admin/backtest/{session_id}
  - go100_paper_trading_sessions 세션 요약
  - fallback: v4_desk_backtest_results
  - go100_daily_equity 일별 자본 변화
  - go100_paper_trades 거래 목록 + 종목별 집계
  - go100_signal_log 시그널 로그
  - 모든 테이블 graceful fallback

POST /api/go100/pending-configs/{hypothesis_id}/approved
  - go100_strategy_hypotheses.status = 'approved' UPDATE
  - reason body 파라미터 (선택)

POST /api/go100/pending-configs/{hypothesis_id}/rejected
  - go100_strategy_hypotheses.status = 'rejected' UPDATE
  - reason body 파라미터 (선택)
```
