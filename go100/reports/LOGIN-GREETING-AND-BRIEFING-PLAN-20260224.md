# 로그인 시 인사·브리핑 기획 보고

**작성일**: 2026-02-24  
**목적**: 사용자 로그인 직후 가벼운 인사와 짧은 브리핑을 제공해 첫인상을 친절하게 하고, 당일 컨텍스트를 바로 파악할 수 있게 한다.

---

## 1. 현황 정리

### 1.1 로그인 후 흐름 (현재)

| 단계 | 경로/동작 | 비고 |
|------|-----------|------|
| 1 | `/auth/callback` — token 수신, getMe, authStore.login | |
| 2 | `router.replace("/dashboard")` | 로그인 성공 시 대시보드로 직행 |
| 3 | 대시보드 로드 | `getDashboardSummary` 등으로 카드 렌더 |

- **인사**: 대시보드 상단 `BaekogiWelcomeBanner`에서 시간대별 인사(좋은 아침/오늘도 좋은 하루 등) + displayName + 총자산/오늘 수익 + 빠른 액션 4개.
- **한계**: “방금 로그인했을 때”와 “이미 로그인된 상태로 대시보드 새로고침”을 구분하지 않음. 로그인 직후만의 가벼운 인사·브리핑이 없음.

### 1.2 활용 가능한 데이터

| 데이터 | 출처 | 브리핑 활용 |
|--------|------|-------------|
| 사용자명 | authStore.user | 인사 시 이름 |
| 총자산·오늘 수익 | dashboard summary | 포트폴리오 한 줄 |
| 보유 종목 수, 최근 체결 | dashboard summary | “보유 N종목, 최근 매매 …” |
| 자동매매 상태, 활성 전략 수 | dashboard summary (system) | “자동매매 꺼짐” 등 한 줄 |
| 미확인 알림 유무 | (선택) 알림 API | “읽지 않은 알림 N건” |
| 시장 지수 | (추후) index_daily 등 | “오늘 KOSPI …” 한 줄 |

## 2. 기획 방향

### 2.1 목표

- **로그인 직후 1회**: 가볍게 인사 + 최소한의 브리핑으로 “들어왔구나” 인지와 당일 컨텍스트 제공.
- **가벼움 유지**: 강제 모달·긴 읽기·다단계 플로우 없이, 토스트 또는 대시보드 상단 1~2블록으로 끝.

### 2.2 인사

- **시점**: 로그인 성공 후 대시보드로 이동한 직후, 1회만.
- **내용**: 시간대별 인사 + 사용자명. (기존 `getTimeGreeting()` 활용 가능.)
- **표현 예**: “좋은 아침이에요, OOO님!” / “OOO님, 오늘도 좋은 하루 되세요!”

### 2.3 브리핑 (한 줄~세 줄 수준)

다음 중 **1~3가지**를 짧게 조합. (구현 단계에서 우선순위 적용.)

| 순위 | 항목 | 예시 문장 |
|------|------|-----------|
| 1 | 포트폴리오 한 줄 | “총 자산 1,234만 원, 오늘 +2.3%예요.” |
| 2 | 자동매매/전략 상태 | “자동매매 꺼져 있어요.” / “활성 전략 2개가 돌아가고 있어요.” |
| 3 | 오늘 추천 액션 1개 | “백테스트 결과 확인해 보는 건 어때요?” / “계좌 연결하면 실거래를 시작할 수 있어요.” |
| (선택) | 미확인 알림 | “읽지 않은 알림 2건이 있어요.” |
| (추후) | 시장 한 줄 | “오늘 KOSPI 전일 대비 +0.5%로 시작했어요.” |

- **데이터**: 대시보드 진입 시 이미 호출하는 `getDashboardSummary`로 대부분 충족. 별도 “브리핑 전용 API”는 1단계에서는 생략하고, 프론트에서 summary 기반 문장 조합으로 구현 가능.

## 3. UX 옵션 비교

| 방식 | 장점 | 단점 | 권장 |
|------|------|------|------|
| **A. 토스트(Toast)** | 가볍고, 화면 레이아웃 변경 없음. 자동 사라짐. | 길면 잘리거나 스크롤 필요. | ✅ 1단계 인사용으로 적합 |
| **B. 대시보드 상단 “오늘의 브리핑” 카드** | 브리핑 2~3줄 수용, 접기 가능. | 배너와 역할이 겹칠 수 있음. | ✅ 브리핑 본문용 |
| **C. 백억이 위젯 자동 첫 메시지** | 백억이 톤 유지, 대화로 이어가기 좋음. | 위젯 열림/자동 메시지 구현 필요. | 2단계에서 검토 |
| **D. 모달** | 강조 가능. | 무거움, 가벼운 인사에는 부적절. | ❌ 비권장 |

**제안 조합**

- **1단계**: 로그인 직후 1회 **토스트**로 인사(“OOO님, 좋은 아침이에요!”).  
- 동시에 대시보드 상단에 **“오늘의 브리핑”** 한 블록(1~3줄) 노출.  
  - “로그인 후 첫 방문일 때만” 또는 “당일 첫 대시보드 진입 시 1회” 노출로 제한하면, 매번 새로고침 시에는 기존 `BaekogiWelcomeBanner`만 보이게 할 수 있음.

## 4. 기술 포인트

### 4.1 “로그인 직후” 판별

- **방안 1 (권장)**: auth callback에서 `router.replace("/dashboard")` 전에 `sessionStorage.setItem("loginJustNow", "1")` 설정.  
  대시보드 마운트 시 `loginJustNow` 확인 후 인사 토스트 + 브리핑 표시, 확인 후 `sessionStorage.removeItem("loginJustNow")`.
- **방안 2**: 전역 플래그(authStore 등)에 `justLoggedIn: true` 설정 후 대시보드에서 소비 시 false로 리셋.

### 4.2 “당일 첫 대시보드 진입” (선택)

- `localStorage`에 `lastDashboardDate` 저장.  
  오늘 날짜와 다르면 “오늘 첫 방문”으로 간주하고 브리핑 표시, 이후 `lastDashboardDate` 갱신.

### 4.3 브리핑 문장 생성

- 1단계: **프론트엔드에서** `getDashboardSummary()` 결과로 분기.
  - `portfolio.total_value`, `portfolio.total_profit_rate` → “총 자산 xxx, 오늘 +x.x%.”
  - `system.orchestrator_state`, `system.active_strategies` → “자동매매 꺼짐” / “활성 전략 N개.”
  - 계좌 0개 → “계좌 연결하면 실거래를 시작할 수 있어요.”
- 추후: 백엔드에 `GET /api/v1/dashboard/briefing` 추가해 문장을 서버에서 생성하면, 시장 지수·알림 등 확장이 쉬움.

### 4.4 접근성

- 토스트: `aria-live="polite"` 및 스크린 리더용 짧은 안내 문구.
- 브리핑 카드: 제목 “오늘의 브리핑”으로 구조화.

## 5. 단계별 제안

| 단계 | 내용 | 산출물 |
|------|------|--------|
| **1단계** | 로그인 직후 1회 토스트 인사 + 대시보드 상단 “오늘의 브리핑” 1블록(2~3줄, summary 기반) | callback에 justLoggedIn 플래그, 대시보드에서 토스트 + 브리핑 카드 컴포넌트 |
| **2단계** | 당일 첫 진입 시에만 브리핑 표시(선택), 브리핑 문장 다양화·추천 액션 1개 반영 | lastDashboardDate 로직, 문장 템플릿 보강 |
| **3단계** | (선택) 백엔드 브리핑 API, 시장 한줄·알림 연동 | `GET /api/v1/dashboard/briefing`, 시장/알림 데이터 연동 |

---

## 6. 요약

- **인사**: 로그인 성공 후 대시보드 진입 직후 **1회만** 토스트로 시간대별 인사 + 사용자명.
- **브리핑**: 대시보드 상단 **“오늘의 브리핑”** 카드로 포트폴리오 한 줄, 자동매매/전략 상태, (선택) 추천 액션 1개를 2~3줄로 표시.
- **가벼움**: 모달 없음, 기존 대시보드 데이터만 사용한 클라이언트 조합으로 1단계 구현 가능.
- **구분**: “방금 로그인”은 sessionStorage/플래그로 1회만 인사·브리핑 노출하도록 하여, 새로고침 시에는 기존 웰컴 배너만 유지.

이 방향으로 구현 시 사용자에게는 “들어오자마자 인사받고, 오늘 상태를 한눈에 보는” 경험이 제공된다.
